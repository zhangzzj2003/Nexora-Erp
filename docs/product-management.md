# 产品与 BOM

## 统一身份与管理入口

“基础资料 → 产品与 BOM”（`/workspace/products`）统一管理成品、半成品、组件和待分类产品。左侧展示“产品系列 → 具体产品/子机型”，可新建系列、新建子机型、纳入已有物料、搜索、按类型筛选及分页；右侧展示所选物料的 BOM 版本和可逐层展开的组成明细。系列仅作归组，不记库存，也不限制哪些其他系列可以引用此物料。

产品沿用唯一物料身份：`product_profiles.material_id` 唯一引用原物料。编码、单位、规格、供应商、库存和业务单据继续使用同一个 `material_id`。同一块主板可供多个成品引用，无须重复建档。产品系列与配置选填；没有归组的主板或历史产品仍可独立生产及维护 BOM。

完整资料权限账号只显示统一导航入口；访问旧 `/workspace/boms` 地址时保留查询参数并进入产品工作区。仅有 `production.view`、没有 `inventory.view` 的既有账号继续使用原 BOM 页面，保留原查看与写入权限，不借合并入口扩大权限。产品资料与 BOM 各自检查库存查看和生产查看权限。

## 产品类型与业务用途

成品、半成品、组件是分类，`can_sell`、`can_purchase`、`can_produce` 是独立用途。半成品可以允许销售，不必复制一个“成品”编码。新建/编辑表单显示三项用途；默认全开以保持原有行为，用户明确设置后按设置执行。未纳入产品的原材料继续沿用原流程。

销售报价建立/编辑、销售订单建单（含报价转单）校验销售用途；采购申请建立/编辑、采购订单建单校验采购用途；BOM 启用和新工单建单校验产出物料的生产用途。已存在业务单据的审批、执行、退货和冲销沿原规则办理，禁用用途不重写历史承诺。用途修改与其他产品资料在同一事务中校验编辑版本，记录修改前后值及原因。旧客户端编辑省略用途时保留原值，不能无意恢复已关闭用途。

MRP 对实际缺料建议检查采购/生产用途，既有库存够用时不因用途关闭而凭空产生缺料；用途限制进入来源指纹，改变用途后旧批准计划须重新核对。启用 BOM 的固定下层版本失效时，MRP 来源读取整体返回明确的修订提示，避免计划使用错误默认版本。

## BOM 版本与多层引用

每个具体物料独立维护 V1、V2 等 BOM；同一物料一次只能有一个启用版本。配方包含基准产出数量和直接组件用量，组件可以是原材料，也可以是拥有自身 BOM 的主板、模块或其他半成品。

- `source_bom_id` 表示复制派生的出处。保存完整的新草稿，来源后续变化不会同步改变目标。
- 明细的 `component_bom_id` 表示该组件固定的下层生产配方。该版本必须属于同一个组件物料，且已经启用过；草稿和取消版本不能被引用。
- 未指定下层配方时只要求该组件物料。组成展示可查看它的“当前启用参考”版本，明确表示当前参考，不是历史版本快照。
- 固定下层版本必须在上层启用及创建新工单时仍处于启用状态；其下层固定依赖也递归校验。停用后保留历史可查，但上层的新生产需显式复制修订、改选下层版本，再停用旧上层并启用新版本。不会静默改用新的默认版本。
- 自引用、重复组件、循环引用、超过 20 层、数量精度和单一启用版本继续校验。展开视图一次最多展示 1000 行，并提示截断；不把展开数据作为库存扣减清单。

右侧将产品资料、紧凑版本栏和组成表格整合为一个工作区，通过共享下拉选择器切换版本，默认查看启用版本；展开主板可查看板内材料及按所选上层基准产出的换算用量。固定版本与当前默认参考明确区分。已停用版本仍可以查看明细和下层历史组成。历史版本列表、复制派生、启用、停用和取消草稿收进“版本管理”弹窗，沿用原权限和断线禁用规则；资料编辑从“产品资料”进入。组成区直接显示基准产出和直接组件数，领料与版本说明可按需展开；左侧名称不重复显示，独立配置和产品类型仍保留。

**BOM 配方版本不等于实物硬件版本。** 同一物料编码的库存按可互换管理，固定下层 BOM 约束生产配方，不声称约束现存实物批次的制造版本。功能、接口或客户要求导致不可互换的板卡必须使用不同物料编码。当前不增加按 BOM 版本分库存、指定制造版本批次领料或同一物料多版本同时启用。

## 仓库与生产闭环

默认采用半成品独立生产入库再总装的流程：

1. 主板工单按主板 BOM 领用裸 PCB、芯片等材料，签收、质检、完工入库，形成主板库存。
2. 整机 BOM 引用主板物料及所需配方版本，同时加入外壳、螺丝等直接组件。
3. 整机工单只固定并领用主板、外壳、螺丝，不同时扣减板内的裸 PCB 和芯片。
4. 主板完成正式成本结算后，其成本随主板库存传入总装；总装费用再计入整机，避免重复计算材料。
5. 允许销售的主板可以直接走原销售订单、出库和成本流程，与总装领用共享同一份库存。

工单继续固定 `bom_id` 和直接组件需求。BOM 已发布明细不可原地修改，因此下层固定引用也随该历史版本保存；新的默认配方不改写既有工单。MRP 已有多层净需求展开，先使用半成品库存，缺口才产生生产建议及下层材料需求；多层计划展开不等于自动执行、签收或入库。

## 草稿、权限与兼容

产品、原 BOM 页面共用 `BomEditor.vue`、公共单据弹窗与 Pinia 草稿。产品工作区固定目标产出物料；复用 BOM 可跨产品复制，但保留每行明确的下层版本约束。更换组件时清理不属于新组件的配方编号。快捷新建产品只带回产出物料，保留已有组件及用量。失败不清草稿；账号、实例、证书或权限变化阻止迟到响应回填。

联合编辑同时检查产品和物料版本，任一冲突整笔回滚。产品目录使用服务端分页，完整读取系列目录；当前页数量不冒充系列总数。创建后可以定位位于其他页的新产品。表单标题与底部操作固定，正文独立滚动；窄窗口逐级减少列数。

“纳入已有物料”复用公共自适应物料选择器，默认显示一行资料摘要；可按需查看或收起资料，更换物料、重新打开弹窗时自动收起资料卡，产品归组及用途草稿保持不变。

| 接口 | 权限与行为 |
| --- | --- |
| `POST /api/v1/products/query` | `inventory.view`；文字、类型和系列筛选，分页默认 20、最多 100 |
| `GET /api/v1/products/{id}`、`/{id}/changes` | `inventory.view`；当前资料、独立用途、审计 |
| `POST /api/v1/products`、`PUT /api/v1/products/{id}` | `catalog.manage`；物料/产品联合建档编辑，独立用途为严格布尔值 |
| `/api/v1/product-models` 及详情/变更/写入 | 沿用库存查看、资料管理权限；系列编辑保留版本与原因 |
| `GET /api/v1/boms`、`/{id}` | `production.view`；按产出物料筛选，含复制来源和组件固定配方编号、版本及状态 |
| `POST /api/v1/boms` | `bom.create`；完整明细，可选复制来源及逐行下层配方 |
| `/api/v1/boms/{id}/activate\|retire\|cancel` | 沿用各原有权限，启用增加固定下层依赖校验 |
| `GET /api/v1/product-bom-features` | 已登录即可读取协议能力，不返回业务数据 |

桌面主进程写入独立用途或固定下层版本前先检查服务能力，旧服务未升级时在写入前拒绝，不允许未知字段被忽略而产生虚假的成功。能力请求期间切换账号或实例也不继续写入。

## 迁移与验证边界

第 104 版曾增加产品扩展、系列、产品审计及复制来源，并去重纳入所有历史 BOM 产出物料。第 105 版仅追加独立用途和可空下层配方引用，历史用途默认全开，下层引用保持空，不猜测旧配方的依赖版本；不改写物料编码、库存、工单或审计 JSON。未约束历史配方不因新空字段改变 MRP 来源指纹。迁移可重复执行。

回归覆盖独立用途及旧客户端省略字段、联合冲突回滚、错误/草稿/停用下层版本、默认升版后的拦截和历史工单不变、多层查看的数量和循环、统一导航权限，以及主板生产签收入库 → 正式成本结算 → 整机生产 → 主板独立销售的真实接口链路。

本期不增加虚拟件直接展开扣料、自动跨层执行工单、物理版本库存隔离、自动配置组合生成或产品删除。本机已安装服务与安装包需单独更新；代码通过验证不等于已升级运行中的服务。
