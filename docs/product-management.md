# 产品与 BOM

## 统一身份与管理入口

“基础资料 → 产品与 BOM”（`/workspace/products`）统一管理成品、半成品、组件和待分类产品。左侧按“搜索与筛选 → 新建系列／子机型 → 产品树”组织，每个具体系列提供独立的编辑与删除图标，底部只保留“纳入已有物料”；右侧展示所选物料的 BOM 版本和可逐层展开的组成明细。系列仅作归组，不记库存，也不限制哪些其他系列可以引用此物料。

系列的新建和编辑使用聚焦表单，不重复展示系列目录；编辑保留修改原因与变更记录，保存成功关闭表单。同系列收起重开保留未保存草稿；切换编辑目标、新建、账号、服务实例或卸载页面都会撤销旧系列读取，失败不会展示其他系列的旧表单。

系列是目录节点，同时最多展开一个主项，展开其他系列或“未归组产品 / 半成品”时自动收起上一项；再次点击已展开主项可全部收起，不再提供“展开全部”。所有主项仍常驻显示，主项与子项保留 10px 垂直间距。展开操作不筛掉目录数据，也不切换右侧 BOM；选择新产品、保存后定位或产品归属变化时只展开对应主项。搜索和类型筛选作用于全部产品，保存子机型后仍刷新全目录并按保存回执定位，不自动切成某个系列的筛选。点击系列、未归组或具体子机型会确定下一次新建的归属，明确选择未归组时不继承右侧旧产品的系列。

产品列表子项展示名称、类型、停用状态及有差异的配置，已归组和未归组产品均不展示物料编号；仍支持按编码搜索，右侧产品资料和 BOM 明细保留编号供核对。

主项展开与收起采用 220ms 自然高度过渡，并配合淡入淡出和箭头旋转；空系列及未归组采用相同动画。收起中的子项立即停止鼠标、键盘和读屏交互，快速切换以最后一次操作为准。系统启用“减少动态效果”时直接切换，不播放过渡。

动画回归可先用 `NEXORA_PREVIEW_PORT=8785 npm run docs:preview-ui` 启动隔离预览，再设置 `NEXORA_PLAYWRIGHT_MODULE` 运行 `node tests/product-tree-motion-browser.mjs`；测试逐帧检查双向高度、快速切换、焦点及减少动态效果，不写入正式数据。

目录使用独立滚动条，接近底部时按服务端分页追加，不显示页码和每页条数选择；不足一屏且没有折叠隐藏子项时继续补充，失败保留已有节点并提供重试。收起节点不会因内容高度变小而自动拉取全部分页，仍可向下滚动或点击“加载更多”。累计节点与单页响应分别保存，跨页去重并校验物料身份；加载后续页不改变折叠状态、所选产品或右侧 BOM。尚有后续页且某组没有已加载成员时提示继续加载目录，不误报空系列。正常末页不再显示“已显示全部”或留下空的加载区域；若并发资料变更导致末页去重后数量与总数不一致，保留实际加载数并提示刷新。搜索、类型及会话变化会使旧请求失效，资料写入后从第一页重新读取。仅产品页采用紧凑标题，桌面下目录与 BOM 分别滚动，其他页面标题保持原样。

产品沿用唯一物料身份：`product_profiles.material_id` 唯一引用原物料。编码、单位、规格、供应商、库存和业务单据继续使用同一个 `material_id`。同一块主板可供多个成品引用，无须重复建档。产品系列与配置选填；没有归组的主板或历史产品仍可独立生产及维护 BOM。

新建和编辑子机型使用产品场景表单：维护类型、系列、配置、业务用途、分类编码、名称、单位、规格型号、备注和修改原因。供应商绑定、封装、品牌／制造商、制造商料号、固定电子参数、环保及非标准扩展属性在“物料管理”维护；产品请求省略这些字段，编辑既有资料时沿用原值，不清空或重绑。分类已有的规格模板及历史规格仍可填写和查看，没有模板时不展示空白规格框；成品类型不会因为物料编码属于电子类就出现元件参数。

完整资料权限账号只显示统一导航入口；访问旧 `/workspace/boms` 地址时保留查询参数并进入产品工作区。仅有 `production.view`、没有 `inventory.view` 的既有账号继续使用原 BOM 页面，保留原查看与写入权限，不借合并入口扩大权限。产品资料与 BOM 各自检查库存查看和生产查看权限。

切换产品时只读取当前资料和对应 BOM，不等待产品审计历史。变更记录在打开“产品资料”时按需读取，使用独立加载、失败及重试提示；同一份已加载资料关闭再打开不重复请求。切换产品、重新读取资料或会话失效后撤销旧历史读取并重新确认范围，旧响应不能进入另一产品。

## 产品类型与业务用途

成品、半成品、组件是分类，`can_sell`、`can_purchase`、`can_produce` 是独立用途。半成品可以允许销售，不必复制一个“成品”编码。新建/编辑表单显示三项用途；默认全开以保持原有行为，用户明确设置后按设置执行。未纳入产品的原材料继续沿用原流程。

销售报价建立/编辑、销售订单建单（含报价转单）校验销售用途；采购申请建立/编辑、采购订单建单校验采购用途；BOM 启用和新工单建单校验产出物料的生产用途。已存在业务单据的审批、执行、退货和冲销沿原规则办理，禁用用途不重写历史承诺。用途修改与其他产品资料在同一事务中校验编辑版本，记录修改前后值及原因。旧客户端编辑省略用途时保留原值，不能无意恢复已关闭用途。

MRP 对实际缺料建议检查采购/生产用途，既有库存够用时不因用途关闭而凭空产生缺料；用途限制进入来源指纹，改变用途后旧批准计划须重新核对。启用 BOM 的固定下层版本失效时，MRP 来源读取整体返回明确的修订提示，避免计划使用错误默认版本。

## 业务用途在单据中的生效范围

选料接口随授权物料目录返回 `can_sell`、`can_purchase`、`can_produce`，不依赖产品管理页的搜索、分页或是否打开。公共物料选择器由业务明确指定用途：新选料隐藏不符合用途的产品；已选中的失效草稿行保留物料资料、数量和价格，标记“不可销售／采购／生产，请重新选择”，不静默删除或替换。当前客户端保存产品或停启子机型后，立即同步已加载的业务候选与 BOM 生产资格；其他客户端的修改在下一次刷新后显示，服务端写入始终按最新用途校验。

| 用途 | 生效入口 | 保留的历史或库存行为 |
| --- | --- | --- |
| 允许采购 | 采购申请新建/修改、直接采购订单、申请转订单、设备维护转采购申请、MRP 采购建议与转申请；旧接口无订单采购入库也校验 | 已有采购订单的收货、入库、退货与冲销继续履约 |
| 允许销售 | 报价新建/修改、报价转订单、直接销售订单、售后换货新建/修改中的替换销售物料 | 已有销售订单出库、销售退货与冲销，以及已批准售后换货继续履约；维修耗材按库存领用，不要求可销售 |
| 允许生产 | BOM 启用、新生产工单、生产计划新建/修改/下达、MRP 制造建议与转工单 | 允许维护未启用的 BOM 草稿和查看历史配方；已有工单、领退料、报工、质检及完工继续办理；作为上层组件领用现有库存不要求该组件仍可生产 |

MRP 参数显式选择“采购”或“生产”时，页面禁用不符合用途的方式，后端保存时再次校验。“自动”保留，实际产生缺料时按最终供给方式检查；现有库存足够时不强迫采购或制造。用途变化仍进入 MRP 来源指纹，旧批准计划必须重新核对。

用途只影响对应新业务，不按成品/半成品类型猜测。仓库其他入出库、调拨、盘点、库存资料及历史单据查询保留完整物料目录。产品软删除沿用既有规则：禁止新生产，销售与采购仍按独立开关执行。此改动不迁移用途值，也不改写库存或历史单据。

旧服务未返回用途字段时，客户端兼容原候选范围，保存结果仍以服务端为准；要完整获得新选料过滤与补充拦截，需同时更新客户端和服务端。代码与自动化测试通过不代表已更新本机正式安装服务。

## BOM 版本与多层引用

每个具体物料独立维护 V1、V2 等 BOM；同一物料一次只能有一个启用版本。配方包含基准产出数量和直接组件用量，组件可以是原材料，也可以是拥有自身 BOM 的主板、模块或其他半成品。

- `source_bom_id` 表示复制派生的出处。保存完整的新草稿，来源后续变化不会同步改变目标。
- 明细的 `component_bom_id` 表示该组件固定的下层生产配方。该版本必须属于同一个组件物料，且已经启用过；草稿和取消版本不能被引用。
- 未指定下层配方时只要求该组件物料。组成展示可查看它的“当前启用参考”版本，明确表示当前参考，不是历史版本快照。
- 固定下层版本必须在上层启用及创建新工单时仍处于启用状态；其下层固定依赖也递归校验。停用后保留历史可查，但上层的新生产需显式复制修订、改选下层版本，再停用旧上层并启用新版本。不会静默改用新的默认版本。
- 自引用、重复组件、循环引用、超过 20 层、数量精度和单一启用版本继续校验。展开视图一次最多展示 1000 行，并提示截断；不把展开数据作为库存扣减清单。

右侧将产品资料、紧凑版本栏和组成表格整合为一个工作区，通过共享下拉选择器切换版本，默认查看启用版本；展开主板可查看板内材料及按所选上层基准产出的换算用量。固定版本与当前默认参考明确区分。已停用版本仍可以查看明细和下层历史组成。历史版本列表、复制派生、启用、停用和取消草稿收进“版本管理”弹窗，沿用原权限和断线禁用规则；产品头部提供“编辑产品”直接维护资料，“产品资料”继续用于查看和审计。版本栏提供“修订 BOM”，带出当前所选版本的基准数、用料及下层固定配方，保存成完整新草稿并按真实创建回执选中该版本；不会因并发出现更高版本而误选他人的草稿。旧版本及历史工单保持不变，新草稿仍须另行启用。关闭后再次修订同一来源会沿用未保存输入；已取消版本不可修订。组成区直接显示基准产出和直接组件数，领料与版本说明可按需展开；左侧名称不重复显示，独立配置和产品类型仍保留。

尚无 BOM 的子机型在右侧直接展示首建表单，填写基准产出、版本说明并在公共物料表格中选择组件、调整用量及固定下层配方；也可“复用已有 BOM”后继续在同一区域调整。物料资料沿用自适应选择组件，展开和收起后同步重测行高，避免留下多余占位。首次保存为草稿，成功后展示真实创建版本，失败保留输入。已有版本时，右上角“新建版本”先选择“空白创建”或复用已有 BOM（含当前子机型的历史版本），再在公共单据弹窗中编辑。版本号由服务端依次分配，不由页面猜测；复用保留来源追溯，原版本及历史工单不变，新版本仍须另行启用。切换子机型、账号或实例后，旧选择和迟到保存回执不能写回新的目标。

组成表首列展示物料编号，展开箭头或叶节点紧邻编号前方，层级缩进与分支线也保留在此列；后续依次展示组件名称、用量、单位和下层生产配方，名称列保持对齐。展开入口与编号分别响应点击，点击编号后复用仓库的只读物料详情与台账弹窗；下层展开行同样按该组件的真实物料身份查看，不替代配方版本入口。此入口查询完整范围，不沿用库存页面的仓库、日期或来源筛选；切换产品、BOM 版本或离开页面时关闭详情并撤销旧读取。

组成列表的下层行采用 220ms 高度和透明度过渡，箭头同步旋转，表格外框随子行展开、收回。各分支独立展开，快速反向沿当前高度继续；收起中的旧行立即停止交互，焦点回到仍可见的上层展开按钮。切换产品或版本清除旧动画，系统“减少动态效果”下直接切换。列表仍复用公共表格，并按分支路径固定行身份；为真实行高过渡仅此表关闭纵向虚拟渲染，保留原有 1000 行展示上限、列宽及横向滚动。

列表动画验收：用 `NEXORA_PREVIEW_PORT=8787 npm run docs:preview-ui` 启动隔离预览，设置 `NEXORA_PLAYWRIGHT_MODULE` 后运行 `node tests/product-bom-motion-browser.mjs`。测试覆盖表格及行的双向中间高度、多层独立分支、离场焦点与锁定、快速反向、产品与版本切换、减少动态效果和窄窗口，不连接正式业务服务。

**BOM 配方版本不等于实物硬件版本。** 同一物料编码的库存按可互换管理，固定下层 BOM 约束生产配方，不声称约束现存实物批次的制造版本。功能、接口或客户要求导致不可互换的板卡必须使用不同物料编码。当前不增加按 BOM 版本分库存、指定制造版本批次领料或同一物料多版本同时启用。

## 仓库与生产闭环

默认采用半成品独立生产入库再总装的流程：

1. 主板工单按主板 BOM 领用裸 PCB、芯片等材料，签收、质检、完工入库，形成主板库存。
2. 整机 BOM 引用主板物料及所需配方版本，同时加入外壳、螺丝等直接组件。
3. 整机工单只固定并领用主板、外壳、螺丝，不同时扣减板内的裸 PCB 和芯片。
4. 主板完成正式成本结算后，其成本随主板库存传入总装；总装费用再计入整机，避免重复计算材料。
5. 允许销售的主板可以直接走原销售订单、出库和成本流程，与总装领用共享同一份库存。

工单继续固定 `bom_id` 和直接组件需求。BOM 已发布明细不可原地修改，因此下层固定引用也随该历史版本保存；新的默认配方不改写既有工单。MRP 已有多层净需求展开，先使用半成品库存，缺口才产生生产建议及下层材料需求；多层计划展开不等于自动执行、签收或入库。

## 系列与子机型的删除、停用

系列和子机型都采用软删除，保存删除时间、操作人、原因以及前后审计快照，版本同步递增；正常目录不再显示已删除项。物料、编码、库存、BOM 和历史工单不会被物理删除。删除的系列编码以及子机型对应的物料身份继续保留，不重新分配；当前不提供恢复入口。

- 系列删除由后端在写事务中校验完整的未删除子机型数量，搜索、类型筛选及分页不会缩小校验范围。有子机型时提示“请先删除子机型，再删除系列”；停用的子机型仍计入数量。
- 子机型若被未删除上层产品的启用 BOM 固定引用，删除被阻止，必须先修订或停用上层 BOM；仅停用上层产品仍受保护。已删除上层产品的 BOM 只作历史，不再阻止后续子机型删除，也不进入新 MRP 配方或新版本循环校验；已有工单供给和领料预约仍保留。草稿中的旧固定引用也会在后续启用时重新校验，已删除子机型不能再作为固定生产配方。删除不改写任何历史配方或已有工单。
- 子机型停用／启用复用现有生产用途 `can_produce`，不引入第二套 BOM 总开关。停用保留目录、采购／销售用途及各 BOM 版本状态，禁止该子机型的新工单、BOM 版本启用及 MRP 新制造；上层仍可领用已有半成品库存，原有工单继续履行。
- 确认操作需 `catalog.manage`、当前版本和原因；过期版本、重复删除或新增关联返回明确错误。删除与建档／改归组在同一数据库写锁边界串行执行，不能通过并发请求把子机型挂到已删除系列。
- 已删除的子机型不能从旧 BOM 入口重新纳入；已删除系列不能再分配给新建或修改的子机型。工单选择与 BOM 详情使用 `product_can_produce` 及时关闭不可用的建单入口，服务端仍在写入时再次校验。

## 草稿、权限与兼容

产品、原 BOM 页面共用 `BomEditor.vue` 与 Pinia 草稿；首建使用工作区内嵌外壳，后续升版和原 BOM 页面沿用公共单据弹窗，物料控件、校验及保存逻辑共用。产品工作区固定目标产出物料；复用 BOM 可跨产品复制，但保留每行明确的下层版本约束。更换组件时清理不属于新组件的配方编号。快捷新建产品只带回产出物料，保留已有组件及用量。失败不清草稿；账号、实例、证书或权限变化阻止迟到响应回填。

联合编辑同时检查产品和物料版本，任一冲突整笔回滚。产品目录使用服务端分页，完整读取系列目录；当前页数量不冒充系列总数。创建后可以定位位于其他页的新产品。表单标题与底部操作固定，正文独立滚动；窄窗口逐级减少列数。

“纳入已有物料”复用公共自适应物料选择器，默认显示一行资料摘要；可按需查看或收起资料，更换物料、重新打开弹窗时自动收起资料卡，产品归组及用途草稿保持不变。

| 接口 | 权限与行为 |
| --- | --- |
| `POST /api/v1/products/query` | `inventory.view`；文字、类型和系列筛选，分页默认 20、最多 100 |
| `GET /api/v1/products/{id}`、`/{id}/changes` | `inventory.view`；当前资料、独立用途、审计 |
| `POST /api/v1/products`、`PUT /api/v1/products/{id}` | `catalog.manage`；物料/产品联合建档编辑，独立用途为严格布尔值 |

| `GET /api/v1/boms`、`/{id}` | `production.view`；按产出物料筛选，含复制来源和组件固定配方编号、版本及状态 |

## 迁移与验证边界

第 104 版曾增加产品扩展、系列、产品审计及复制来源，并去重纳入所有历史 BOM 产出物料。第 105 版仅追加独立用途和可空下层配方引用，历史用途默认全开，下层引用保持空，不猜测旧配方的依赖版本；不改写物料编码、库存、工单或审计 JSON。未约束历史配方不因新空字段改变 MRP 来源指纹。迁移可重复执行。第 106 版追加系列与子机型的软删除事实，旧记录默认未删除；不迁移或改写库存、工单及原审计 JSON。

回归覆盖独立用途及旧客户端省略字段、联合冲突回滚、错误/草稿/停用下层版本、默认升版后的拦截和历史工单不变、多层查看的数量和循环、统一导航权限，以及主板生产签收入库 → 正式成本结算 → 整机生产 → 主板独立销售的真实接口链路。

本期不增加虚拟件直接展开扣料、自动跨层执行工单、物理版本库存隔离、自动配置组合生成。本机已安装服务与安装包需单独更新；代码通过验证不等于已升级运行中的服务。

## 只读物料参数

BOM 组成名称下直接展示规格型号、封装、品牌、制造商料号、技术参数、分类规格和扩展属性；展开下层组成时使用该层物料自身的资料。物料编号继续保留独立详情入口，原 BOM 行的编号、名称、数量和单位不被当前档案覆盖。产品资料与公共库存物料详情同样直接展示实际填写的参数，长备注可按需展开；零值、布尔值、未知／不适用／待确认和历史字段均保留原语义。

只读行优先使用对应业务接口随行返回的 `material`，旧响应仅按真实物料 ID 从已有授权缓存回退，不逐行发起网络请求。单据与 BOM 中的附加信息标记为“当前档案参数”；它不是审批时的历史参数快照，也不会进入送审正文或摘要指纹。其他入库、公共审批详情、库存来源单据及生产材料详情复用同一展示组件，按原业务查看权限返回对应物料资料，不借此开放完整物料目录、供应商绑定或价格。
