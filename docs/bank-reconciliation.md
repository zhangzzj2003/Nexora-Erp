# 银行流水勾对基础规则

第 69 版提供单公司、人民币口径的人工银行流水登记与逐笔勾对。银行账户以永久编码区分；同一账户的银行交易号唯一。流水金额以元、两位小数文本保存，入账为正，出账为负。批量接口最多接收 500 笔，并在一个 ORM 写事务中完成，遇到重复交易号整批回滚。桌面页目前提供逐笔登记；批量导入接口已具备，但尚未提供 CSV 解析或银行直连。

勾对来源包括订单收付款记录及历史分户收付款记录。系统按应收/应付方向换算银行收支方向，要求金额和方向完全一致；一笔银行流水与一笔收付款同时只能有一个有效勾对。匹配人必须填写依据。撤销时追加独立撤销记录，原勾对和流水均保留，可重新勾对。全部业务读写使用 SQLAlchemy 声明式模型与 ORM 会话，结构迁移仍使用 SQLite DDL。

查看、账户登记、流水登记、勾对和撤销分别要求 `bank_reconciliation.view`、`.account`、`.record`、`.match`、`.reverse` 权限；内置管理员与财务员默认获得。桌面入口按查看权限控制，服务端对每个写操作再次校验权限。

这是一套人工凭据核对能力。银行流水仍由操作员录入，系统无法验证银行文件真伪，也未连接银行、导入文件、处理手续费或跨笔拆并单、计算银行对账单余额及未达账项；勾对结果不自动改变应收应付或生成总账凭证。当前总览一次返回全部记录，大数据量时还需分页。正式银行对账和余额调节表仍需后续规则与实施。
