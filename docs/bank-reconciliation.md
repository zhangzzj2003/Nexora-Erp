# 银行流水勾对与余额调节规则

第 69 版提供单公司、人民币口径的人工银行流水登记与逐笔勾对；第 70 版增加 UTF-8 CSV 文件预检、整批导入和来源批次。银行账户以永久编码区分；同一账户的银行交易号唯一。流水金额以元、两位小数文本保存，入账为正，出账为负。批量接口最多接收 500 笔，并在一个 ORM 写事务中完成，遇到重复交易号整批回滚。桌面页可逐笔登记，也可选择文件预检后确认导入。

CSV 第一行必须精确为 `transaction_id,occurred_on,amount,counterparty,note`，日期使用 `YYYY-MM-DD`，金额使用十进制文本，文件不得超过 1 MiB、500 笔。允许 UTF-8 BOM 及符合 CSV 规则的引号字段。预检返回行数、前 20 笔摘要、文件 SHA-256 和账户内重复交易号，不写入数据；正式导入重新验证文件及冲突，任一失败整批回滚。每批记录原文件名、原始字节摘要、操作者和时间；流水指向导入批次。相同账户、相同原始字节文件不能重复导入。系统不保存原文件，须由操作方保留银行原始凭据。

```csv
transaction_id,occurred_on,amount,counterparty,note
BANK-001,2026-10-03,125.00,甲公司,货款
BANK-002,2026-10-03,-20.00,乙公司,退款
```

勾对来源包括订单收付款记录及历史分户收付款记录。系统按应收/应付方向换算银行收支方向，要求金额和方向完全一致；一笔银行流水与一笔收付款同时只能有一个有效勾对。匹配人必须填写依据。撤销时追加独立撤销记录，原勾对和流水均保留，可重新勾对。全部业务读写使用 SQLAlchemy 声明式模型与 ORM 会话，结构迁移仍使用 SQLite DDL。

第 71 版增加银行账户的总账科目绑定、银行期初及版本审计、银行流水与已过账总账分录的多对多同向等额分组勾对、撤销、余额调节快照和独立复核。绑定须选择启用的资产类借方科目，启用日须等于已确认总账期初的启用日；一个总账科目只能绑定一个银行账户。没有期初未达项时，银行与总账期初必须相等。已有勾对或调节表后不能修改绑定。绑定以前的银行流水不可作为当期来源。

第 72 版允许在绑定的同一事务内迁入最多 100 笔启用日前的期初未达项。每笔标明“银行已记、企业未记”或“企业已记、银行未记”、原交易日期、有符号人民币金额、原凭据编号和说明；同一账户同侧依据编号不可重复。银行期初加企业已记未达净额，必须等于总账期初加银行已记未达净额，否则整笔绑定回滚。保存后期初明细不可改写，存在期初明细的账户绑定也不可重设。旧账户不自动推断期初未达项；已有勾对或调节表的账户不能事后补录，须保留原规则下的绑定和历史证据。

期初银行已记项只能用自启用日起同方向、合计等额的已过账总账分录核销；期初企业已记项只能用相应银行流水核销。每项最多一次有效核销，可选择 1 至 20 笔来源；来源不能同时参与其他有效期初核销或总账分组勾对。撤销核销追加原因与操作者记录，不删除迁入项或核销历史。按截止日计算调节表时，只有全部核销来源均已进入该日期范围，该期初项与对应来源才一起退出未达清单；较早的历史快照仍按当时未达状态计算。核销与撤销会改变适用日期的来源指纹，旧复核表保留并显示来源变化。

调节预览以银行期初加截止日以前的银行流水计算银行期末，以已确认总账期初加同范围的已过账借贷分录计算账面期末。未勾对银行流水及银行已记的期初项属于“银行已入账、企业未入账”，未勾对总账分录及企业已记的期初项属于“企业已入账、银行未入账”；出账以负金额表示。调整后银行余额等于操作员填报的银行对账单期末余额加未勾对总账分录和企业已记期初项净额，调整后账面余额等于已过账账面期末余额加未勾对银行流水和银行已记期初项净额。银行填报期末还必须等于系统银行流水累计期末，才允许复核通过。相反收支方向不能合并勾对，每组两侧各最多 20 笔，合计必须相等。撤销只追加撤销记录，原勾对不删除；已复核调节表的来源因此失效时仍保留原快照并提示来源变化。

`POST /api/v1/finance/bank-balance/accounts/{id}/binding` 设置绑定并可提交 `opening_items`；`/opening-items/{id}/clearances` 核销期初项，`/opening-clearances/{id}/reverse` 撤销核销；`/preview` 预览；`/ledger-matches` 与 `/ledger-matches/{id}/reverse` 管理分组勾对；`/reports` 留存不可改写的计算快照，`/reports/{id}/decision` 由不同账号复核通过或驳回。复核通过前重算来源指纹，来源变化、填报余额或调整结果不符时返回冲突；同日的新复核表以追加决策取代旧表，不覆盖原记录。`/overview` 汇总绑定、期初未达项及核销、勾对、调节表、复核和失效证据。第 72 版新增四张静态 ORM 模型表；所有业务读写使用 ORM 会话。

查看、账户登记、流水登记、勾对、撤销、编制调节表和复核分别要求 `bank_reconciliation.view`、`.account`、`.record`、`.match`、`.reverse`、`.reconcile`、`.review` 权限；内置管理员与财务员默认获得。桌面入口按查看权限控制，服务端对每个写操作再次校验权限。

桌面端可在“余额调节表与复核记录”按报表导出 UTF-8 CSV。文件使用保存时的不可改写快照列出余额汇总、未勾对流水和分录、期初未达项及勾对与核销来源，同时标注当前复核状态、来源是否变化和复核记录；即使后续来源变化，历史金额仍按原快照导出。导出要求 `bank_reconciliation.view`，外部凭据文本会转义以避免表格公式执行。CSV 是内部核对资料，不是银行原始对账单，也不代替对当前来源的重新复核。

这仍是一套人工凭据核对能力。文件由操作员取得，系统无法验证银行文件真伪，也未连接银行；手续费须先登记为银行流水及已过账总账分录，系统不会自动入账。跨币种、多控制科目、自动匹配与银行直连尚未实现。勾对、期初核销和调节不会自动改变应收应付或生成总账凭证。总览一次返回全部记录，大数据量时还需分页。
