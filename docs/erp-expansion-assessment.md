# ERP 后续模块评估与实施门槛

本文是进一步扩展的评估清单。客户归属、统一分页、财务核对、MRP/人工排程、质量处置及采购分级审批已在本轮保留分支实现并验证，见 [本轮验收](erp-batch-acceptance.md)；其余候选能力不表示已经实现。每一项在业务规则确定后，仍须按独立需求分支交付接口、权限、页面、测试和文档。当前内部试用以单公司、多仓库和在线局域网服务端为边界；[实机验收清单](lan-host-acceptance.md)尚未全部完成。

## 建议的需求顺序

以下顺序是**候选实施顺序**，不是已确定的会计政策。先由业务负责人确认样例单据、期初数据和核对口径，再为每个具体需求建分支。

1. **成本与业务金额基础。** 确定采购价差、历史无价单据的补价权限、库存计价方法、退货沿用成本规则，以及生产在制与完工批次的分摊口径。先让库存数量、库存金额、工单成本和销售成本可从原始单据相互追溯；缺价时明确显示待核价，不能默认为零。
2. **总账与凭证。** 科目和期间基础资料已交付，详见 [总账基础规则](ledger-foundation.md)；正式期初独立审核确认已交付，见 [期初余额规则](opening-balances.md)；继续补充业务分户期初核对、摘要和附件规则。为已确认业务单据设计可追溯的凭证来源；手工凭证已提供借贷平衡、独立审核、过账和冲销，见 [手工凭证规则](manual-journals.md)；[业务来源凭证](business-journals.md)已提供映射、重复生成保护和来源快照，仍须独立审核过账。现有收付款记录只是人工登记，不能据此推断银行实际入账。
3. **结账与财务报表。** 期间结账、历史核价/分摊锁定、倒序重开和归档已提供，见 [期间结账规则](period-closing.md)；[损益结转](profit-transfers.md)已提供期间末草稿、独立审核、来源保护和倒序更正。已过账科目明细与试算平衡已提供，见 [总账报表规则](ledger-reports.md)；继续设计资产负债、损益等报表。报表金额要能下钻到凭证及原始单据；未结期间和缺价单据需显式标注。未形成可核对的总账前，不把业务汇总称为正式财务报表。
4. **质量、售后和 CRM。** 先补充不合格品处置与返工来源，再根据实际退换修流程定义售后单与库存、应收的关系。CRM 从客户资料、跟进记录和商机开始评估；只有销售订单和客户资料稳定后才连接报价或预测，避免出现第二套客户主数据。
5. **审批、设备、经营报表与人力资源。** 审批先选一个真实单据及金额阈值试点，并保持服务端权限校验。设备维护需明确设备台账、停机和工单关联。经营报表复用同一套已确认业务单据。人力资源涉及独立的人员权限和保留期限，先确定数据责任人及访问边界。

## 多公司与分公司设计门槛

目前数据库和权限均按单公司运行。增加组织维度前，先用真实业务样例逐项回答：物料与往来单位由谁维护、哪些仓库可被哪个组织使用、订单和库存流水归属哪个组织、用户可查询哪些组织、跨独立公司是否需双方各自确认单据。共享资料不等于共享库存或共享财务余额；跨公司交易需要双方可审计的单据与冲销关系。未确认这些边界前，不直接给现有表批量增加公司字段。

## 每个后续需求的验收门槛

- 提供至少一条完整正常流程和一条更正或冲销流程，写明谁有权操作、何时确认、如何追溯原单据。
- 金额变动在服务端事务内核对数量、状态、权限与并发；对缺价、重复确认、余额不足和跨期更正有明确结果。
- 前后端共享类型、接口错误语义、页面、单元测试及文档同步；真实桌面与设备验收分别记录，不用构建通过代替。
- 财务报表和跨公司功能上线前，使用业务方提供的期初数据与对账样例做结果核对；本仓库目前没有这些验收样例。
