# 后端 ORM 迁移清单

现有业务数据访问迁移已完成，本版的 129 张表有静态声明式模型，包含科目、期间、第 41 版手工凭证，第 42 版期初余额、明细和审计，第 43 版期间结账证据，第 44 版业务科目配置、配置审计和来源快照，以及第 45 版损益结转配置、配置审计和结转来源。第 46 版新增公司报表配置、配置审计和归档三张表；第 47 版新增辅助档案、两类审计、科目规则及分录归属五张表；第 48 版新增分户期初、原单、审计及资金四张表；第 49 版新增 MRP 参数、参数审计、计划、计划审计及转单五张表；第 50 版新增联系人、跟进、商机、报价、报价明细及变更证据六张表；第 51 版新增处置、处置审计、处置成本分配、返工携入四张表；第 52 版新增售后方案、审计和客户物品保管三张表；第 53 版新增设备、维护计划、维护工单、停机和审计五张表；第 54 版增加物料永久分类流水和资料审计两张表及物料参数列；数据库为第 54 版，共 129 张静态模型表。接口字段、权限和单据状态没有因 ORM 改变。模型不在运行时反射，也不在启动时创建或替换历史表。已移除旧完工接口的 SQLite/ORM 兼容读取。

底层例外仅限数据库结构升级与初始数据迁移、SQLite 事务/外键/超时设置、在线备份 API 和备份完整性诊断。这些操作不属于业务查询或单据写入，不能用普通 ORM CRUD 替代。备份中的实例身份读取通过 ORM，仍用只读连接，错误路径不创建空库。

回归测试检查业务模块不再导入旧连接或执行 SQL 字符串，并模拟数据库写入后的故障，核对库存、单据、订单额度及跨模块来源整体回滚。并发收货、入库、退货、调拨、完工与收付款继续由同一写锁保护。

`backend/tests/test_orm_boundary.py` 自动扫描整个 `backend/app`，新功能目录也在范围内。检查覆盖直接 SQL、字符串变量及简单别名、SQLAlchemy 文本构造器和底层驱动导入，保留基于模型的 `select`、`update`、`delete` 等 ORM 会话操作。模型声明的 `server_default=text(...)` 只允许在默认值位置；备份只允许固定的 `PRAGMA integrity_check`；事务模块只允许现有固定 SQLite 配置与事务开始语句。不能把这些文件作为业务 SQL 的整体豁免。此静态检查不代替接口的权限、精度、并发及回滚测试，也不声称能识别所有运行时动态生成的代码。

每个转换模块必须核对旧接口字段、错误状态、权限、金额精度、来源审计和并发行为。只读会话使用同一快照；写会话在业务核对前取得 SQLite 写锁，异常回滚并释放连接。后续数据库支持需另外实现对应驱动与迁移，不因引入 ORM 就声称 MySQL 已可用。
