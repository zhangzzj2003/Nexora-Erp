# 实例级单据编号

服务端为 30 类核心单据和独立资金记录保存只读 `document_no`。客户端提交业务信息后读取完整单号，不计算前缀、日期或流水；内部 ID、外部参考号、供应商批号仍各自保留。

## 首次管理员设置

新服务和升级至数据库第 88 版的旧服务初始均为“未设置”。管理员登录或恢复会话后进入必填设置页，可退出登录或切换服务端。普通账号保留原查询权限，并看到管理员尚未设置的提示。设置前服务端拒绝业务写入，旧客户端也不能绕过；登录、账号权限管理、编号设置和服务运维仍可使用。

首次设置使用居中的三步卡片：选择编号风格 → 设置编号日期时区 → 确认并保存。前两步只更新本地草稿，按钮和表单回车均不会提前保存或补号；可返回已完成步骤修改，语言切换和保存失败保留选择。确认页展示完整单号示例、规则锁定及历史补号提示。短窗口允许纵向滚动，减少动效偏好下直接切换内容。常规系统设置仍使用完整规则表单。

首次引导的编号风格选项使用独立卡片，四边完整绘制，悬停与焦点高亮继承卡片的四个圆角，选中颜色与禁用状态沿用 Naive UI 和当前主题；常规系统设置仍保留连体单选按钮样式。

语言仅用于第一次打开表单时预选拼音或英文风格，时区默认跟随服务端本机。选择完成后提交才保存。失败保留草稿；并发修改返回冲突后重新读取版本。其他管理员已完成设置时，等待页面读取已确认规则后进入工作台；切换实例后丢弃旧服务端的迟到响应。系统设置页可查看规则，管理员在尚未生成单号时可修改。

生成第一张单号或完成历史补号后，风格、时区模式和指定时区永久锁定。语言、客户端时区和单据状态变化均不会改写已有号码。规则和序列属于数据库，备份、恢复及服务重装沿用原规则。

## 日期与历史补号

- 本机模式每次生成读取服务端系统当前时区，系统时区调整后新单日期随之变化。
- UTC 模式固定使用 UTC 日期。
- 指定模式使用随服务打包的 `tzdata` IANA 数据，例如 `Asia/Shanghai`、`America/New_York`，自动处理夏令时。不同系统使用同一套指定时区数据。

新单创建时间由服务端保存为 UTC，并用同一时刻换算编号日期，避免午夜跨日。历史补号按原创建时刻、ID 稳定排序，分别初始化每类各日序列。SQLite 原有无偏移时间按 UTC 处理；异常或缺失时间使用 `00000000`，不伪造升级日期。设置响应返回补号及异常日期数量。

迁移只增加可空列、唯一索引和配置/序列表；管理员提交规则时在一个事务内补齐全部历史主单。重复启动和设置不重复编号。补号不修改数量、金额、状态、批次分配、固定 JSON 快照或来源指纹。

## 接口与边界

认证后 `GET /api/v1/system/document-numbering` 返回配置状态、锁定状态、版本、设置人及时间、服务器当前时间、编号日期预览、可选时区和补号数量。

管理员专用 `PUT` 输入：

```json
{"style":"pinyin","timezone_mode":"specified","timezone":"Asia/Shanghai","version":0}
```

`style` 接受 `pinyin/english`；`timezone_mode` 接受 `server/utc/specified`，前两种模式的 `timezone` 必须为空。无修改权限返回 403，非法参数或时区返回 422，版本冲突或已锁定返回 409。桌面固定操作路径、请求体和响应编号均在受限桥接校验。

全部新主单通过 ORM `before_flush` 边界分配。SQLite 写事务使用 `BEGIN IMMEDIATE`，并发客户端不能读出相同流水。接口在原有授权完成后补充展示字段；历史快照原样保留。业务列表、选择器及详情展示已保存单号，搜索保留原 ID 与参考号，并增加主单和关联单号。相关采购/总账/MRP CSV 和报价 PDF 也展示号码。

## 溯源范围

库存台账、实物批次历史和财务来源已补充可识别来源单号，为按批次串联业务提供标识基础。完整的批次溯源页面、跨生产混料/拆分关系图及端到端链路查询仍是独立后续需求，不能仅凭单据编号推断实物批次归属。
