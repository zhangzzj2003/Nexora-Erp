# 按仓库库存预警

库存预警是在线读取时的现存量检查。每个仓库与物料组合有一条规则；未配置的组合不参加预警，也不能据此判断库存充足。规则不改变库存、不生成采购单，不提供服务端主动推送、邮件或未来需求预测。

## 数量与状态

后端从 `StockMovement` 静态 ORM 模型读取已确认流水，逐笔使用 Decimal 汇总每个仓库与物料的数量，不用浮点 SUM，不跨仓库抵消。草稿、未来采购或生产需求不计现存量；冲销追加流水后，下一次读取反映当前数量。此规则与 MRP 物料级安全库存参数独立。

| 条件 | 显示状态 | 距阈值差额 |
| --- | --- | --- |
| 规则停用 | 已停用 | null，显示“不参与预警” |
| 启用且现存量小于等于零 | 缺货 | max(0, 阈值 − 现存量) |
| 启用且正现存量小于阈值 | 低库存 | 阈值 − 现存量 |
| 启用且正现存量达到阈值 | 正常 | 0 |

阈值按物料当前单位填写，非负、最多三位小数且不超过一百万。零阈值允许，但零现存量仍为缺货。阈值以文本保存，负零归一化为 `0.000`。历史审计保留当次仓库名称、物料名称和单位，不随基础资料改名而覆盖；资料单位修改不会换算已保存阈值，操作员须重新核对规则。

## 权限、版本与证据

查看入口 `/workspace/inventory-warnings` 与读取接口要求 `inventory.view`。维护还要求 `inventory_warning.manage`；默认管理员和仓库员具备维护权限，只有维护权限而没有查看权限的账号仍被拒绝。

首次配置携带 `version: 0`，成功后版本为 1。修改或启停携带当前版本并填写 1–200 字原因，成功后递增；同一组合不可重新绑定。过期版本、并发首次配置或重复创建返回 409，不覆盖其他人的规则。规则与前后快照、原因、操作者和时间在同一 ORM 写事务保存，故障整体回滚。不提供删除历史审计的接口。

库存数量变化不会增加规则版本，修订记录描述的是阈值和启停，而非库存变化。详情中的“核对本仓库与物料的库存流水”打开库存台账，并重设仓库/物料及清除日期/来源筛选，便于核对全量流水；台账与预警属于各自读取快照，持续发生业务时数量可能变化。

## 接口

| 方法与地址 | 行为 |
| --- | --- |
| `GET /api/v1/inventory/warnings` | 同一读取快照返回已配置规则、选项、读取时间与各状态/未配置计数 |
| `GET /api/v1/inventory/warnings?warehouse_id=<正整数>` | 只返回该仓规则与范围计数，选项仍包含全部资料 |
| `GET /api/v1/inventory/warnings/rules/{warehouse_id}/{material_id}` | 当前规则、当前数量及完整修订证据；未配置返回 404 |
| `GET /api/v1/inventory/warnings/events` | 服务端核对事件，按编号倒序，每页默认 50、最多 100 条；可按 `warehouse_id` 筛选，用 `before_id` 翻到更早事件，返回 `next_before_id` |
| `PUT /api/v1/inventory/warnings/rules/{warehouse_id}/{material_id}` | 正文只含 `version`、十进制 `threshold`、布尔 `enabled`、`reason` |

参数和正文无效返回 422，未授权返回 401/403，来源不存在返回 404，版本冲突返回 409。桌面桥接使用固定操作名和路径，并验证响应形状；不接受页面传入的任意 SQL、路径或预警计算结果。

## 桌面使用与升级

默认筛选缺货和低库存，可切换全部规则、正常或停用。配置在页内填写；冲突保留输入和旧版本，返回列表读取最新证据后再修订。读取失败不把旧结果当新数量；同账号断线失效数量和详情，保留未保存阈值与版本。切换账号或权限清除共享数据，迟到响应不得覆盖新会话。

已登录且具有 `inventory.view` 权限的桌面窗口每 60 秒独立读取全部仓库的预警规则。首次成功读取会对现有缺货和低库存弹出应用内提醒；之后只提醒新进入缺货/低库存、或从低库存恶化为缺货的组合。多项变化合并为一条提醒，持续异常不重复弹出；恢复正常后再次跌破阈值会重新提醒。断线、退出、换号、换服务端或撤权会清除比较基线，迟到响应不提醒；读取失败时保留上次基线，等待下一次成功读取。窗口关闭后停止窗口轮询，未打开应用时不弹应用内提醒。

窗口失焦且操作系统支持通知时，同一轮状态变化另由 Electron 主进程显示一条系统通知；窗口聚焦时仅显示应用内提醒。通知只含缺货与低库存项数，不在锁屏上显示仓库或物料；点击通知打开主窗口。主进程只接受当前主窗口的请求，校验数量范围。系统禁用通知、开发版 Windows 缺少开始菜单标识或未签名 macOS 安装包时，通知可能无法显示或无法响应点击，应用内提醒仍可用。关闭窗口后桌面轮询停止，因此不承诺无人登录、窗口关闭或客户端离线时主动送达；桌面重新打开后仍可翻阅服务端事件历史。

第 68 版起，服务端启动后立即核对一次，此后约每 60 秒在独立读快照中逐仓逐物料计算状态，再用短写事务保存每条规则的最近观测。首次观测为缺货/低库存、从正常或停用进入异常、以及低库存恶化为缺货时，追加不可覆盖的事件；持续异常、缺货恢复为低库存和正常状态不重复记事件。事件固定当时仓库和物料名称、数量、阈值、规则版本及前后状态，之后改名不覆盖旧记录。读取失败会记录服务日志并在下一周期重试；服务停止期间不能观察到又恢复的短暂异常，也不把事件生成时间当作库存流水发生时间。桌面预警页可查看并翻阅本仓或全部仓的服务端事件；接口沿用 `inventory.view`，断线、换号或撤权会失效旧结果。事件是服务端历史记录，不会由服务端主动推送到操作系统、邮件或未登录的客户端。

数据库第 55 版新增 `inventory_warning_rules`、`inventory_warning_changes`，当时静态模型共 131 张；第 68 版追加最近观测与事件两张 ORM 表，当前共 151 张。组合唯一性、外键和历史索引由版本迁移建立，旧库不自动猜测阈值或补造过去的事件。客户端和服务端须同步升级。测试覆盖精度、仓库隔离、草稿/冲销、权限、并发、写后故障回滚、升级回滚和桌面会话边界；浏览器临时数据验收不代替业务现场核对或 Windows/macOS 实机验收。
