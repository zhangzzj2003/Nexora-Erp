按上述七页取景，等待表格、图表、字体和数据加载完成，将截图保存为对应 PNG。保留完整窗口视口，不裁掉侧栏、导航或标签；更新素材时同时核对说明和尺寸，并运行官网测试。截图不会自动更新，后续界面改变需要重新取景；构建按图片内容添加 URL 版本，避免更新后继续命中旧素材缓存。

同一控制板场景用 MCU、电阻、电容、裸板及成品解释电子生产。台账展示原料入库、首批领料及完工，成本来源对应领料流水 4–6，完工流水 7 对应结算 401；采购入库 #101、库存三行原料入库、应付来源及采购凭证共享 4800 元依据；总账列表展示来源凭证的不同阶段，取景只覆盖列表，不提供凭证详情编辑。首页是较宽范围的示例经营快照，台账不是首页全部业务的完整历史复现。

这些是浏览器中的真实组件预览截图，**不构成原生 Electron 运行、服务连接或业务过账验收**。生产 API 与真实业务数据不参与取景，官网构建只复制静态 PNG，不发布预览会话。


下方逐项关联保留完整应用外壳，在原工作区内使用 CSS 放大取景，不修改图片中的业务字段。`../source-details.mjs` 保存桌面 640 × 256、手机所选行 340–440 × 112 的取景坐标，以及三个物料各自的行内边界。图片版本与哈希由官网测试校验；更换这三张图后必须在桌面/手机逐行核对物料、来源、数量和金额，更新边界和版本，再运行测试。关联键包含入库 #101 的行号，不能只以共同单号代替项到项关联。大图入口始终打开完整布局。

高清明细使用 `receipts@3x.png`、`inventory@3x.png`、`sources@3x.png`，尺寸 5400 × 3600。在 1800 × 1200 逻辑视口打开预览地址 `?capture=true#/workspace/receipts`（库存为 `/workspace/inventory-ledger`，财务为 `/workspace/financial-sources`），等待页面、表格和字体就绪，点击“导出当前界面高清 PNG”。工具把当前真实 DOM、计算样式及内联品牌资源交给浏览器重新栅格化，以三倍像素无损导出，并保存到三个固定文件名；这是 DOM 界面导出，不是原生 Electron 屏幕捕捉。工具按钮在应用外，不进入图片。

`capture-sink.mjs` 仅在回环预览服务中接受同源 POST，限制 PNG 名称、尺寸和 20 MiB 上限，拒绝任意路径和跨源请求。官网不复制或发布取景代码。更换高清图也要同步 `highResVersion`，逐行复核连线；坐标仍以 1800 × 1200 逻辑像素维护。
