# 库存台账、报表与物料详情

库存台账按物料编号、物料名称、时间、处理人、仓库、单据类型、单据编号、变动、筛选范围结余展示。物料编号位于最左侧，仓库使用较窄默认列宽；时间按设备本地时区显示为 `26/10/13 13:47`，只省略秒数，不作分钟四舍五入。无时区的服务端时间继续按 UTC 解析。

## 物料详情

- 点击台账或库存报表的物料编号，在同一弹窗切换“物料详情”和“台账明细”，不跳转页面。
- 物料资料按编号重新读取当前档案，展示分类、单位、规格、品牌、技术参数和备注；名称中的分隔符不用于推断物料身份。
- 台账入口沿用打开时的仓库、日期、来源筛选，只替换物料并使用独立分页。报表入口限定点击行的仓库和物料：库存余额沿用截至日期、忽略隐藏的开始日期；收发存沿用开始与结束日期。
- 弹窗的读取、错误和分页独立于主表，关闭后保留主表筛选及页码。期初期末取自服务端完整范围汇总，不由本页明细反算。
- 资料和明细分别处理失败，可单独重试。切换账号、服务实例、权限、查询条件或断线时清除详情并使在途请求失效。

## 来源单据

点击台账及物料明细中的单据编号，使用公共单据详情弹窗查看原单内容和审批记录。`GET /api/v1/inventory-ledger/{movement_id}/document` 按库存流水定位业务来源；冲销流水先由冲销记录回溯原单，再读取该原单的冲销审批，不把冲销 ID 当成主单 ID。

查询必须同时满足 `inventory.view`、原领域的单据查看权限及已有客户归属规则。详情只供查看，不提供审批或库存写入按钮。正文沿用原单详情的送审快照；与当前正文有差异时明确提示。历史没有审批记录的业务保留原历史状态，不补造审核过程。不支持的来源、缺失记录、无权或网络失败显示错误及重试入口，不猜测另一张单据。

## 库存报表

库存余额、收发存均将物料编号与名称分列，编号排在最左侧。分页和全量查询返回 `sku`、`material_name`、字符串形式的 `material_id` / `warehouse_id`；保留旧 `material` 文案供兼容调用使用。CSV 与页面使用相同的拆分列，导出仍重新读取完整筛选结果。采购报表保持原有列结构。

报表本身要求 `inventory_report.view`；查看物料资料和台账另需 `inventory.view`。客户端和服务端应同步更新，新来源单据入口及报表稳定编号依赖对应服务端接口。本次没有数据库结构变更。

## 验证

前端测试覆盖列序、字段分离、点击入口、独立分页、完整范围汇总、报表日期范围、失败重试、晚到响应和 IPC 校验。后端测试使用真实 SQLite 业务单据验证原单/冲销定位、领域权限、客户归属、报表分页与完整 CSV；另覆盖全部库存来源的映射和缺失记录。
