# 业务来源凭证规则

已实现单公司、人民币的业务凭证草稿生成。由业务方维护科目映射，服务端从已确认单据重算金额；生成后仍须提交、由另一账号审核并过账。生成不修改库存、应收应付或资金登记，也不证明实物、票据或银行实际到账。此规则用于内部核对，不替代业务方会计政策。

生成的业务凭证可使用与手工凭证相同的[总账附件](journal-attachments.md)接口留存补充凭据；附件不改变来源金额或审核结论。

## 启用与权限

桌面入口为“财务管理 → 总账凭证 → 业务来源与科目配置”。桌面入口要求 `journal.view`，来源读取另要求 `business_journal.view`，配置与生成分别要求 `business_journal.configure`、`business_journal.generate`。管理员、财务员默认获得这三项权限；自定义角色可分开授权。审核、过账、取消及冲销继续使用既有凭证权限。

首次配置前先核对已有手工凭证，避免重复记账；系统无法判断手工凭证是否已经覆盖某张业务单据。选择启用日期后不可改写；启用日前来源只供核对，不能生成。启用日期不能落入已结账期间。允许只配置部分用途，缺少或停用的科目会阻止涉及该用途的来源。配置带版本和变更原因，过时版本、重复保存返回 409；历史保存前后映射、操作者与时间。配置变化不改写已生成凭证的科目快照。

## 金额来源

以下为带符号的入账规则，正金额记借方，负金额记贷方；冲销与退货按真实来源的符号处理，不修改原事件。

| 来源 | 规则 |
| --- | --- |
| 采购入库、采购退货及其冲销 | 库存记移动平均计价变动；应付记订单来源金额的负数；采购价差记“订单金额减库存金额”。 |
| 销售出库、销售退货及其冲销 | 应收记订单来源金额，收入记相反金额；库存记成本变动，销售成本记相反金额。 |
| 其他入出库、盘点、独立调整及其冲销 | 库存与“其他库存变动对方”按相反金额记账。实际用途科目须由业务方核对。 |
| 生产领料、退料、完工及完工冲销 | 库存与生产在制成本按相反金额记账；完工来源须完成成本结算。 |
| 人工与制造费用及其独立冲销 | 在制成本记费用金额，人工或制造费用对方记相反金额。 |
| 应收人工收款、退款及登记冲销 | 资金记有符号登记金额，应收记相反金额。 |
| 应付人工付款、退款及登记冲销 | 应付记有符号登记金额，资金记相反金额。 |

公司内仓库调拨不改变公司总账库存，不生成凭证；仓库核对仍使用库存台账。未确认草稿、仅确认采购收货但尚未入库的单据不产生来源。分位净额为零且没有缺价的来源无需金额凭证。库存缺价、往来来源没有订单单价、缺少对应库存流水或来源金额超出凭证上限时拒绝生成；库存人工核价不能替代订单价格。

库存新增 `accounting_amount`，为每条流水发生前后“物料余额四舍五入到分”的差值。原 `amount` 仍用于流水金额展示，两者可能有一分尾差。例如三件单价 1.005 的入库余额为 3.02，逐件出库的入账差额为 -1.01、-1.00、-1.01，全部出库后总账库存可归零。采购价差承接业务分位金额和库存分位金额的差异；这不等于已经提供完整采购价差分摊模块。

## 核对、生成与更正

来源核对展示用途金额、映射科目、库存流水、订单明细或费用/收付款登记。服务端不接受客户端提交的分录金额、状态或来源证据。客户端仅提交来源键、指纹、配置版本、凭证日期、依据编号及原因；生成事务重新读取并核对全部来源。首次生成及取消草稿后的再生成都使用来源发生日期（UTC），不能通过选择未来日期绕开来源期间。

同一来源最多有一张未取消、未被已过账关联冲销完全抵消的凭证；唯一索引和写事务保护并发生成。重复依据或来源返回 409。来源快照、配置快照、凭证分录与创建审计整体提交，任一步失败都回滚。业务生成的分录不能手工编辑，需取消后重新生成。

提交、审核和过账时重新校验经济来源指纹；期间发生核价或成本变化时拒绝继续处理，须取消旧草稿并重建。已过账来源受统一写事务保护，不能通过撤销核价、改成本结算等操作暗改来源；先建立关联总账冲销，由独立账号审核并过账，才可更正来源。冲销仅在总账形成相反金额，不替代业务单据的实物冲销。重建日期不得早于来源日期及历次已过账关联冲销日期。

业务单据自身的冲销、退货、退款是独立业务事件，按单独来源生成凭证；不能因已有原凭证而漏记。资料更名不改变经济指纹，已生成证据仍保留生成时物料与仓库名称；科目名称及分录继续沿用凭证快照规则。

## 结账与查询

启用范围内、发生日期不晚于期间结束日的非零或缺价来源，必须有期间结束日前已过账且未被完全冲销的有效凭证，才能结账。未生成、草稿、取消、已完全冲销或日期移到后期的凭证均不算覆盖。结账检查返回 `pending_business_sources` 及来源键；未配置业务凭证政策时保留既有结账行为，不自动补造历史凭证。

凭证详情及审计提供 `business_source`，包含来源键、金额证据、科目映射和配置版本。已过账报表继续从凭证与正式期初读取；可下钻核对生成时证据。

接口统一前缀 `/api/v1/finance/business-journals`：GET 根路径读取来源；GET/PUT `/policy` 读取/保存配置；GET `/policy/changes` 读取审计；POST `/generate` 生成草稿。数据库第 44 版新增三个静态 ORM 模型及权限，不反射模型、不自动推断历史科目、不自动过账。客户端与服务端须同步升级。

## 验证与边界

测试覆盖真实采购、销售、退货、费用及冲销金额、尾差、未知成本、生产结算、来源变化、过账锁定、配置版本、并发去重、写入后故障回滚、权限、旧库原子迁移与结账覆盖；桌面测试覆盖精确预览、IPC 字段过滤、失败保留输入、迟到响应和撤权清理。

税费、折扣、多币种、多公司、按物料辅助归属及银行对账仍未实现；客户/供应商及部门/项目辅助归属、历史分户期初、损益结转和公司财务报表已独立提供。初版配置按全公司用途统一映射，所有来源的重放与已过账保护可能随历史数据增多而变慢，尚无大规模性能验收。上线前仍须用业务方真实科目、期初及会计样例验收。

第 48 版新增 `subledger_payment:<id>` 历史单据资金来源，使用现金与应收/应付用途生成，默认带入原单全部往来、部门和项目快照且不能改换或新增归属。有效分户方案的控制科目须与对应用途一致，不能通过改配置切换往来账户。导入历史未结明细本身不生成第二份总账期初；资金冲销仍须按已过账来源更正规则处理，见 [分户期初](subledger-openings.md)。


## 售后维修收费来源

收费维修实际交付结案产生 `after_sales_repair` 应收与 `repair_income` 服务收入来源；整单费用按明确方案，不按物品数量乘价。更正追加 `after_sales_repair_reversal`，保留原已过账来源。两笔须分别生成、独立审核和过账。免费、未交付及取消维修不产生该费用，客户物品不形成库存分录；公司耗材另沿用其他出库来源。见 [售后规则](after-sales.md)。
