# 物料需求计划

提供单公司、全部仓库合并数量的 MRP：按日汇总需求与预计供给，展开启用 BOM，合并共享组件后扣库存，按参数形成采购或生产建议。结果固定保存，独立审核后可转现有采购申请和工单草稿。计划与转单均不记库存；真实数量仍由原单收发确认。

## 来源与日期

- 已确认或部分交付销售订单的未出库量为需求。只扣有效已确认出库；退货增加实物库存，不重开原销售承诺。
- 未取消采购订单的未入库量、采购申请的未转单量为预计供给。草稿订单也占用申请额度，申请与订单不会重复计算；已确认采购退货减少实物库存，不自动补开原采购承诺。
- 草稿、已下达和进行中工单的剩余未报工目标量为预计供给，按全部未来合格的假设计算。已报不合格数量也耗用原目标，返工未实现。未领的固定组件需求按计划起日计入，不再次展开现有工单 BOM。
- 草稿、待审及驳回原单仍表示已登记的待执行供给，会明确告警；操作者须先核实可执行性，再批准计划。它们不是库存，也不保证到货。
- 原单尚无交期字段，所以编排必须逐项指定未执行销售需求与预计供给的日期，不能默认遗漏。之前 MRP 转入的申请或工单沿用保存的需求日；该日期已逾期时告警，并按新计划起日最早预计到达。
- 可增加最多 500 条手工需求。服务端今天按 UTC；起日须在今天起 730 天内，所有输入日期须在计划起日起 730 天内。同日先供给后需求。

## 数量计算

参数按物料维护：自动/采购/生产、0–365 日历日提前期、安全库存、最小批量和批量倍数。默认自动、其余为 0；自动在有启用 BOM 时生产，否则采购。明确选采购停止展开该物料组件；生产必须有启用 BOM。

全图按低层码归并需求，共享组件处理前先收齐所有父项；不按成品树分别占用同一份库存。每个日期的净缺口为 `max(0, 毛需求 + 安全库存 − 期初预计数量 − 同日预计供给)`。建议量至少达到最小批量，再向上取批量倍数；余量带入以后日期。

生产建议按建议数量/BOM 基数乘组件用量，向上取三位小数，沿用工单需料规则；组件日期为父项投放日。应投放日等于需求日减提前期；早于计划起日则显示提前期不足，实际建议投放日取起日。警告不会伪装成可行排程。无工作日、产能、损耗、良率或交期保证。

单公司全部仓库库存来自有效流水 Decimal 汇总。目标仓库可能仍需调拨，计划不自动调拨。最多 2000 个物料、2000 条未执行销售需求、2000 条供给、5000 条工单待领来源；BOM 最深 20 层，结果最多 5000 日期行、1000 建议。单条建议或组件需求不得超过一百万，超限明确拒绝。尚无大规模性能验收。

## 固定结果、审核与更正

编排 → 计算保存草稿 → 共用单据审批送审 → 按固定模板逐步审核、核准、批准或驳回 → 转单。草稿和驳回计划可提交；取消保留历史。编制及曾提交计划的账号持有当前步骤按钮权限时可以批准或驳回，同一人可办理多个已授权步骤。送审和审核要求非空依据，最多五百字；共用审批携带审批版本，取消和转单携带业务版本，并发旧版本返回 409。待审或已批准计划先撤回才能取消。

每次计算固定输入、材料/BOM/参数/库存流水/原单快照、来源指纹、日期行、建议、警告及使用口径。日期行可查看该日销售、手工、父项建议和工单待领来源，以及计算时参数、BOM 和库存流水。CSV 与固定行集一致，包含 UTF-8 BOM 并保护公式前缀。参数和计划均保留操作者、时间、原因及前后记录。

提交、批准、转单在写事务中重新检查来源指纹。库存、原单状态/数量、BOM、参数、基础资料变化或起日已过期时，新建计划重算；历史结果不覆盖。取消本计划已转入的原单也使其失效。同计划自身正常转单不使剩余建议失效；另一个计划会看到新增预计供给与工单待领，旧结果因而失效。

## 转单边界

只能从完成本单独立审批且仍匹配来源的固定建议转单，客户端不能改数量、物料或 BOM。生产须选择目标仓库；采购生成一行采购申请草稿。每建议只能成功转一次，原单、来源关联、计划版本和审计同一 ORM 事务保存，首次执行审批状态与事件也同事务保存，后续剩余建议沿同一批准继续分批转换，不重复追加执行事件；任何失败整体回滚。取消原单后仍不能重用旧建议，须重算新计划。计划有未取消原单时不可取消。

MRP 来源采购申请不能修改，以保持建议数量与来源一致；需要更正时先按原单依赖流程取消，再重算。后续审批、转采购订单、收货入库、工单下达/领退料/报工仍使用已有原单权限和流程。转单不会自动批准或执行原单。

## 桌面与权限

生产管理入口 `/workspace/material-planning` 只要求 `mrp.view`，该权限授予公司计划范围的材料、销售/采购/工单承诺、库存和参与对象名称读取，无需各原模块查看权限。配置、编制、提交、审核、取消、转单分别要求 `mrp.configure/create/submit/review/cancel/convert`；转单还须拥有目标 `purchase_request.create` 或 `work_order.create`。

默认管理员全部拥有，生产计划员除审核外拥有，财务员只读。第 49 版同时给生产计划员增加采购申请查看、建立、提交和取消权限，使其能够执行采购建议；不授予采购申请审核权限。自定义角色不自动加权。

桌面用 Pinia 管理来源、日期草稿、固定结果和操作；同账号断线保留输入，来源与检查失效；换实例/换号/撤权清除敏感状态，迟到响应不回写，排队写入再次核对同一账号和服务端。审批刷新保留未保存编排；已打开转换弹窗固定计划和业务版本，详情切换或批准撤回后必须重新打开。输入失败保留，来源刷新保留仍存在来源的已填日期，新来源保持空日期要求确认。参数保存冲突须重新打开查看新版本。

## API 与升级

统一前缀 `/api/v1/production/mrp`：GET `/options`、`/plans`、`/plans/{id}`、`/plans/{id}/check`、`/plans/{id}/changes`、`/policies/{material_id}/changes`；PUT `/policies/{material_id}`；POST `/plans`、`/plans/{id}/cancel`、`/plans/{id}/convert`。送审、批准、驳回和撤回使用 `/api/v1/system/document-approvals/MrpPlan/{id}/{action}`；旧 `/submit|approve|reject` 入口保留权限及业务版本检查后返回 409。旧批准计划剩余建议须独立重审，已全部转单的历史计划不补造审批。输入无效 422，越权 403，不存在 404，状态、来源、版本及重复冲突 409。

第 49 版增加五张静态 ORM 表：`mrp_policies`、`mrp_policy_changes`、`mrp_plans`、`mrp_plan_changes`、`mrp_conversions`，共 109 张。升级不造历史计划、不改库存，失败回滚，重复启动幂等。所有业务查询与写入统一声明式模型与 ORM 会话；客户端与服务端须同步升级。

这交付数量与日期计划及审核转单，不等同于有限产能排产、车间调度、完整质量管理、返工、在制与跨期成本，后续缺口见[模块盘点](erp-expansion-assessment.md)。浏览器验收仅使用独立临时数据库与模拟数据，不代替业务方真实交期和数量验收。
