# 不合格品处置与返工

本模块已提供生产报工不合格数量的分批报废、返工、独立审核、成本分配与来源更正。使用单公司、人民币与现有移动加权平均成本；不提供完整质量体系、抽检方案、实物批号、售后或有限产能排产。

## 数量与审批

来源必须是已确认、未冲销且有不合格数的生产完工单。草稿不占用数量；提交、批准、确认均占用，驳回、撤回、取消、更正释放数量。同一来源各有效处置数量不得超过原不合格数。数据库写锁下重算额度，并发只允许符合额度的操作提交。

每张单只选报废或返工一种方式；同一来源可分多张单。数量最多三位小数，正文包括依据编号、缺陷记录、处理说明及原因。返工可选择目标仓库和追加材料的总数量，不按原 BOM 再领一遍材料，也不能把本次不合格成品作为组件。

流程为草稿 → 统一送审 → 模板规定的独立审核/核准/批准 → 确认；草稿或驳回可修订。中间步骤仍占用原数量；待审或已批准须先撤回再修订或取消。编制、修订或提交过正文的账号及管理员持有当前步骤按钮权限即可审批。修订和动作携带旧版本，过期返回 409；正文、阶段、操作者、原因及完整前后快照在同一 ORM 事务保存。材料名称、单位及数量在编制/修订时记录快照；提交重新核对并冻结原质检来源。审批后正文不能直接改写。

报废确认保留隔离来源，不增加可用库存。返工确认只建立关联工单草稿，不记入库、不凭空记消耗。返工工单继承成品身份和本次处置数量，需料仅为明确选择的追加材料。返工工单仍须独立批准才能下达，方案编制、编辑、提交和转单人员按子工单当前步骤按钮权限审批。无追加材料时，下达即进入生产中；有材料时按原有领料流程推进。返工后重新报工、检验，只有合格数进入目标仓库；再次不合格仍走同一处置流程。

## 成本与总账

报废成本必须明确选择：正常报废由合格品承担，或独立报废损失。返工固定为携带来源成本。系统不替用户判断正常损失范围，也不默认独立损失为零。

原工单全部报工且不合格数量全部确认处置后才能新建成本结算；未取消的草稿、提交、批准及驳回单也须处理完毕。设总成本为 C、合格数 A、正常报废数 N、独立报废数 E、返工数 R：

- 合格品成本池为 `C × (A + N) / (A + N + E + R)`，四舍五入到分；按合格完工批次数量分摊。
- 剩余成本按独立报废与返工数量分摊，保存逐处置单金额。正常报废的处置分配金额为 0，因为其成本已进入合格品。
- 各成本池按累计数量分配尾差，合格批次、独立损失、返工携带成本之和严格等于原总成本。
- 全部不合格且全部独立报废或返工时允许结算，没有虚构合格入库。没有合格品时不能选择“由合格品承担”。

返工总成本为携入成本加实际追加领料、人工和制造费用。原工单未结算时，携入金额及返工总成本为未知，禁止返工结算，不能用 0 替代。结算保存四类 ORM 快照：完工分配、处置分配、追加材料及费用来源、返工携入。原结算存在有效下游返工结算时不能冲销。

独立报废提供 `quality_loss:<处置编号>` 业务凭证来源，借记显式配置的 `quality_loss` 科目、贷记在制品；未固定来源成本则阻止生成。科目映射仍由财务明确配置，不预置法定费用分类。草稿须独立审核并过账；已过账来源对应结算更正前，须先过账关联冲销。返工携带是公司内在制品成本来源关系，不重复产生费用凭证。

## 更正、锁期与升级

更正已确认处置须先独立送审并批准固定原因，执行时仍须冲销原成本结算。需求分支已接入返工工单独立审批：子工单正在审批或已经批准时，须先撤回子单审批，再更正上游处置；上游更正不能静默取消尚有有效批准的工单。返工还须取消/冲销全部报工及后续处置、取消领退料草稿、完整退回追加材料并冲销人工/制造费用，之后将关联工单取消并保留历史链接。不得直接取消返工工单而释放源数量。原报工存在提交、批准或确认处置时不能冲销。

已关闭期间保护原报工日期、处置确认日期及成本分配日期。结账检查阻止截至期末尚未固定成本的已确认处置，结账证据归档保存处置正文和历史分配；后续更正不覆盖旧归档。时间沿用 UTC。

数据库第 51 版新增 `quality_dispositions`、`quality_disposition_changes`、`quality_cost_allocations`、`production_rework_sources` 四张静态 ORM 表，并给工单结算增加 `rework_amount`，合计 119 张模型表。旧结算不自动重算或推断旧不合格成本；如需为已结算来源建立新处置，须按依赖与期间约束先冲销旧结算。历史版本迁移、失败回滚及外键完整性都有测试；客户端和服务端须同步升级。

## 接口、桌面与权限

路由在 `app/production/quality.py` 装配，规则在 `quality_rules.py` 复用调用方 ORM 会话；业务 CRUD 无直接 SQL。

| 接口 | 权限 |
| --- | --- |
| `GET /api/v1/production-quality`（来源、处置及材料/仓库选项） | `quality.view` |
| `GET /api/v1/production-quality/dispositions/{id}` | `quality.view` |
| `POST /api/v1/production-quality/dispositions` | `quality.create` |
| `PUT /api/v1/production-quality/dispositions/{id}` | `quality.create`，旧版本与原因 |
| `POST …/{id}/submit` | 旧接口检查权限与业务版本后返回 409，改走统一审批 |
| `POST …/{id}/approve`、`reject` | 旧接口检查权限与业务版本后返回 409，改走统一审批 |
| `POST …/{id}/post` | `quality.post` |
| `POST …/{id}/cancel`、`reverse` | `quality.cancel`、`quality.reverse` |

动作载荷为 `version`、`reason`。管理员默认全部权限；计划员可查看、编制、提交、取消，财务可查看及审核，仓库可查看及确认。处置查看不自动授予成本金额查看；金额要求 `production_cost.view`。生产工单、成本及报工仍使用原模块权限。

桌面入口为 `/workspace/production-quality`，放在生产分类。使用 Pinia 共享状态、固定 IPC 操作与字段白名单；从原质检建立，详情可核对冻结正文与逐次变更。读取失败清除旧证据，断线保留同账号表单和修订版本，换号或撤权清除草稿，迟到读取及保存不能污染新会话。受保护的动作先读取最新证据，再携带旧版本提交；失败保留原因。

验证覆盖混合损失/返工尾差、全部不合格、再次不合格、零追加材料、未知携入、独立审核与权限、数量/版本并发、故障整体回滚、迁移回滚、总账过账来源保护、关闭期间证据、IPC 注入与会话失效。

## 统一审批接入

`QualityDisposition` 的通用审批查询、送审、分步审核、驳回与撤回沿用 `quality.view` / `quality.submit` / `quality.review`，更正送审与撤回沿用 `quality.reverse`。送审和审核原因必填且最多二百字。正文固定原质检、处置数量、成本处理及追加材料快照；成本分配金额不进入通用审批摘要。编辑人员从原审计恢复，新旧草稿均遵守独立审批。审批投影同时更新原阶段、业务版本及追加审计。

确认及更正在原 ORM 事务核对固定批准，子工单、隔离数量、原审计和审批执行事件共同回滚。旧待执行批准不能绕过新流程，旧已确认单仅保留原历史；需要更正时建立单独审批，不补造其原批准。桌面使用共用审批弹窗，保存失败保留草稿与原因，换实例/账号或撤权后旧响应与已打开动作失效。
