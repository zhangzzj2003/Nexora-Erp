# 正式期初余额初版规则

用于单公司、人民币总账首次启用。业务方自行核对启用试算表与科目表；不自动推断库存、客户供应商、订单或银行初始余额，也不预置法定科目。这是内部操作规则，真实会计样例仍须业务方验收。

## 首次启用与更正

- 只能在尚无已过账凭证时建立。启用日固定为最早会计期间的开始日期，且该期间必须开放，存在有效期初方案时不能新增启用日前的期间。
- 同时仅允许一个草稿、待审核、已批准、驳回或已确认方案。取消或撤销释放占用，原记录、明细及历史保留。
- 同一启用科目与完整辅助组合最多一行，不同组合可拆分，只填借或贷一方正金额，另一方为零；金额最多 12 位整数、2 位小数，最多 100 行，借贷总额必须相等。未列出科目视为零；全部为零时明确选择零期初并提交空明细。
- 草稿/驳回可编辑或统一送审，送审后固定一至五步模板，按角色按钮权限逐步审核、核准和批准，全部批准后再确认。建单、编辑或提交过此方案的账号及管理员持有当前步骤按钮权限即可审批。提交、批准、确认时重新核对科目启用状态、期间及余额。
- 确认后固定金额和科目快照，报表计入正式期初，不增加本期发生额。方案尚未确认时拒绝凭证过账；凭证日期不能早于已确认启用日。
- 尚无已过账凭证时可以另行申请撤销审批，固定撤销原因和原确认人员/时间；原确认人员、编制人员及申请人按当前步骤按钮权限审批。批准后才能按相同原因执行撤销确认。撤销后须建立、独立审核并确认替代方案才能继续过账；不能利用空档绕过启用约束。首次凭证过账后不能撤销或重设期初，应使用更正凭证。
- 不曾录入正式期初的旧账可继续过账；报表明确显示只有历史累计口径。历史账已有过账凭证时不能再补设期初，迁移不猜测余额。

所有写操作须填写依据/原因，审批依据最多二百字。统一审批携带审批版本；原状态执行及编辑携带正整数业务版本。待审/批准须先撤回再取消，撤回保留完整过程。冲突返回 409，输入错误返回 422；记录不存在返回 404，越权返回 403。会话在检查前取得写锁，资料、明细和完整前后审计同事务提交；异常整体回滚。重复或并发确认不会产生第二次启用效果。

## 接口与权限

基路径为 `/api/v1/finance/opening-balances`。

| 方法与路径 | 权限 | 作用 |
| --- | --- | --- |
| GET 基路径、GET `/{id}/changes` | `opening_balance.view` | 方案与完整审计 |
| GET `/options` | `opening_balance.create` | 启用科目、最早期间及辅助档案/规则 |
| POST 基路径、PUT `/{id}` | `opening_balance.create` | 建立、修改草稿 |
| POST `/{id}/submit` | `opening_balance.submit` | 旧客户端返回 409，走统一审批 |
| POST `/{id}/approve`、`/reject` | `opening_balance.review` | 旧客户端返回 409，走统一审批 |
| POST `/{id}/confirm` | `opening_balance.confirm` | 确认启用 |
| POST `/{id}/cancel`、`/reverse` | 各自 `opening_balance.cancel`、`opening_balance.reverse` | 取消、启用前撤销 |

管理员与财务员默认拥有以上权限，动作仍须满足职责分离。数据库第 42 版新增三张静态 ORM 表及权限，不自动生成任何启用数据。

## 报表与桌面

“财务管理 → 期初余额”沿用 Pinia、固定 IPC 和 WorkspaceTable，支持搜索、状态筛选、编辑、零余额启用、原因确认与历史详情。断线或忙碌时禁用写操作，失败保留输入；权限撤销或换账号清除共享草稿、选项和旧方案。

试算平衡和科目明细的期初等于已确认启用余额加开始日前已过账分录；本期只计已过账凭证。开始日早于启用日返回 409。查询在同一 ORM 事务读取期初、审计、科目、凭证及期间，CSV 与返回行集一致，元数据包含期初来源。只有 `journal.view` 的报表查看者也能查看当前报表所用期初及完整审计快照，无须期初管理权限，不获得修改能力。

## 验证与限制

测试覆盖完整阶段、独立审核、编辑作者、重复科目及非法金额、零余额、版本冲突、并发建立/确认、创建与确认审计失败回滚、撤销空档拦截、旧账过账保护、早于启用日查询、期初与本期区分、大金额、报表只读权限和旧库升级。桌面测试覆盖固定 IPC、状态白名单、失败保留输入、晚到响应失效、撤权清理及路由授权。

浏览器验收使用独立临时数据库和模拟数据。历史未结单据与总账逐组合勾稽由[分户期初](subledger-openings.md)提供；[业务凭证](business-journals.md)、[损益结转](profit-transfers.md)与[公司财务报表](financial-statements.md)由独立模块提供，附件尚未实现。正式期初本身不改变库存、现有订单的应收应付和资金记录；有效分户方案阻止撤销其绑定总账期初。已结账后不得撤销该期间期初，需先按倒序重开，见 [期间结账规则](period-closing.md)。客户端和服务端需同步升级。


统一审批入口为 `/api/v1/system/document-approvals/OpeningBalance/{id}`，读取使用 `opening_balance.view`，正常送审/撤回使用 `opening_balance.submit`，撤销送审/撤回使用 `opening_balance.reverse`，两种审批审核均沿用 `opening_balance.review`。原确认与撤销仍使用独立执行权限，同事务核对批准正文、原约束并追加执行事实。旧已确认记录保留原历史；旧尚未确认的批准需重新送审，不补造审批。

当前需求分支已接入总账期初逐步审批，仍未完成 29 类整体验收或安装服务升级。新增接口与实际 Vue/Pinia 测试覆盖多步固定、原作者与确认人禁止自审、独立撤销、固定原因、并发、内容篡改、故障回滚、旧客户端及跨实例迟到写入。
