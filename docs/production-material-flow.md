# 生产发料、领料、换料与退料

本需求以生产工单为来源，仓库和生产共用单据与执行事实。仓库的四个列表是同一套业务的不同入口，进入页面本身不授予执行权限。

## 业务边界

| 单据 | 谁办理 | 库存与工单变化 |
| --- | --- | --- |
| 生产发料 | 仓库按已下达或生产中工单建单，批准后分批发出 | 实际发出才扣原料仓库存；记为已发未签 |
| 生产领料 | 生产核对对应发出记录，按实际收到数量签收 | 不重复扣库存；增加工单已签收材料 |
| 生产换料 | 生产选择已签收来源，仓库接收旧料并补发 | 收旧不增加良品库存；新料沿发料与签收流程办理 |
| 生产退料 | 生产申请，批准后仓库按实物分批接收 | 实际接收才增加原仓库存，冲回原出库成本 |

发料、换料和退料使用统一审批。领料单有独立业务编号，但签收只校验实时权限并保存操作证据，不重复审批已批准的发料内容。普通发料不能占用换料补发额度。

## 分批交接

批准发料 100 个，可以先发 60 个、再发 40 个。每次执行保存独立的数量、操作人、时间、来源批次与库存流水。生产收到 58 个时只签收 58 个，其余 2 个持续作为待签差额显示；不能自动入库、自动认领或删除差额。

补送后继续签收原领料单。尚未签收的实物确实退回仓库时，登记关联原发出的交接退回，保留原发出事实与反向入库事实。登记错误使用受控更正，不能用正常退料替代未收到的材料。

关闭余额必须说明原因，只释放未执行部分，不修改已执行记录。已发未签数量不能通过关闭发料单消失。

已知多个来源批次或来源中同时存在已知与未知批次时，分批交接须明确实际批次，不能按编号顺序推断。完整交接可继承已有批次证据，未知部分仍保留证据缺口。新发料产生有效签收或交接退回后，须先更正下游记录才能更改原出库的批次补证；历史直接领料保持原补证规则。

## 换料

换料从已签收且未耗用的来源选择，固定同物料、同单位、等量补发。可对补发后再次损坏的材料再次申请换料，来源链继续保留。

有实物时先收旧再发新。收旧保存隔离交接证据，不把损坏料加回良品库存；完全损耗时，申请须填写损耗依据并审批。已收旧量或获准的无实物损耗量形成补发额度，关联发料单仍须单独批准。生产无须再重填领料表单。

换料分别显示申请量、旧料已交接量、新料已发量、新料已签量和未完成数量。仅发出新料不能视为换料完成。替代型号、返修、退供应商和废料销售不在本期范围。

## 退料与数量口径

正常退料只接收可重新使用的材料。申请或批准不增加库存；仓库接收 4 个就先入库 4 个，余量继续待收。损坏材料走换料旧料交接，不得经正常退料增加可用库存。

工单有效材料量为：

> 累计有效签收 − 正常退回 − 已确认损坏。

完工校验还要排除待退、待换的有效占用。所有来源同时核对已执行数量、其他未完成单据的预留和累计报工所需材料，避免同一份材料重复退换或退回已经耗用的材料。

原 BOM、目标产量和正常材料需求不因换料而变化。已发未签材料属于交接途中，不能用于完工，也不能再次计入尚待发出的物料需求。

## 成本、历史与更正

每次实际发出按对应库存流水保留成本来源，不以最后一次出库价覆盖整张发料单。正常退料按原发出来源冲回；生产损坏保留原材料成本，补发追加实际新料成本，不再重复记同一损坏损失。未知成本继续阻止正式结算。

存在未处理交接差额、未完成领退换业务时，不能最终关闭工单或正式结算；材料条件满足时可以分批报工。

历史已确认领料保留原编号、流水和成本，明确显示“历史直接领料”，不补造生产签收人或签收时间。升级后旧接口不得直接增加生产签收数量。旧未执行单据进入新流程时保留原记录，并重新确认批准内容。

更正追加记录和反向流水，不覆盖已执行历史。已产生签收、退换料、报工、成本结算或期间锁定的来源必须先按依赖顺序处理。提交同时校验版本和防重复标识；审批、剩余额度、来源、批次、流水及审计在同一事务内核对与保存。

## 验收口径

| 场景 | 必须核对的结果 |
| --- | --- |
| 发 60、签 58 | 库存只扣 60，可用于生产 58，待签 2 |
| 200 个库存，正常签收 100，损坏并补签 2 | 库存 98，累计实际发出 102，损坏 2，有效材料 100 |
| 申请退 10，分次收 4 和 6 | 库存分两次增加，申请阶段不提前入库 |
| 网络重试和两个操作者同时提交 | 不重复收发，过期版本拒绝，失败整体回滚 |
| 跨工单、超量、重复来源和批次不足 | 服务端拒绝，不产生部分库存事实 |
| 不同批次成本、历史直接领料及更正 | 数量、成本、编号与来源保持可追溯 |
| 工单与四个仓库列表 | 单据可相互打开，筛选统计和分页使用同一口径 |

## 工单与完工衔接

生产工单与完工质检列表复用仓库管理的状态概览、搜索与仓库筛选。概览先按关键词和仓库统计全部匹配记录，再按状态筛选；不使用表格当前页计算数量。两页沿用现有 Pinia 完整快照与表格本地分页，没有新增服务端查询协议。

工单详情的“创建完工单”直接进入该工单的完工记录范围，并打开预填工单和待报工数量的草稿。该打开意图只消费一次，关闭、刷新或快照更新不会再次重置已填写内容。“查看完工记录”仅查看该工单记录，不自动建单；完工详情可返回来源工单。建单仍检查实时权限、连接状态及工单状态，失败保留草稿。

工单列表分别显示有效领用、已发未签、待发、待安排数量，以及待退换预留和已确认损坏。`pending_dispatch_quantity` 是已有新发料计划与旧领料草稿的未执行量（包含换料补发，关闭余额不再计入）；`remaining_quantity` 是扣除已有计划占用后尚未安排发料的正常需求。批准 100、发出 60、签收 58 时，待发为 40、已发未签为 2、待安排为 0。有效领用是累计签收扣除退回、损坏和预留后的生产核对口径，包含已报工的耗用，不能当作尚未使用的余料。旧服务端缺少待发字段时显示“—”，不将未知量补成零。

`backend/tests/test_warehouse_production_cycle.py` 通过新收发接口串联多仓调拨、分批发料与签收、未签交接退回、换料补发再签、分批退料、两批质检完工及正式成本结算：200 件原料形成 100 件成品，换料损坏 2 件，原料结存 98 件；材料成本 204 元，加人工 10 元，成品结算 214 元。测试同时核对重复请求不扣两次库存、最终完工失败不追加流水、退料申请不提前入库和结算后来源锁定。既有批次、权限、并发、更正、MRP、质量与设备测试分别验证各自边界；接口测试和示例浏览器预览不代替已安装 Electron 客户端及现场验收。
