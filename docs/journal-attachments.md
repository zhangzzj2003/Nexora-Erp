# 总账凭证附件

第 73 版为所有总账凭证增加附件留存，包括手工、业务来源、损益结转和关联冲销凭证。附件是原始凭据的补充证据，不改变分录、金额、凭证版本、审核结论或过账结果，也不自动证明文件真实。文件来源和会计适用性仍需业务方核对。

## 内容与更正

- 每张凭证最多保留 10 个有效附件，单文件须非空且不超过 5 MiB。仅接受 PDF、PNG、JPEG；服务端按扩展名和文件特征核对，拒绝非法 Base64、路径式文件名和格式不一致的内容。特征校验不等于恶意文件扫描，客户端只保存文件，不在应用内执行或渲染附件。
- 上传保存原文件名、文件类型、字节数、SHA-256、原文、非空依据、操作者和时间。相同凭证不能重复上传内容完全相同的有效文件；不同凭证可以引用各自的原文。附件内容与摘要由服务端固定，客户端下载前重新校验字节数和摘要，桌面保存前再核对摘要与格式。
- 上传后不能覆盖或物理删除。传错时填写原因追加一笔撤销，原文仍可由 `journal.view` 权限下载以供审计；同一附件不能重复撤销。撤销后可重新上传正确文件或同一内容。已取消凭证、已结账期间不允许上传或撤销；查看和核对历史附件不受此限制。
- 附件直接存入服务端 SQLite 的静态 ORM 表，随现有在线数据库备份与恢复一并处理；客户端不保存自动同步的附件副本。附件原文不放入凭证列表或审计 JSON 响应，避免普通页面读取时传输大量内容。

## 接口与桌面边界

路径前缀 `/api/v1/finance/journals/{journal_id}/attachments`：

| 方法 | 权限 | 行为 |
| --- | --- | --- |
| GET 前缀 | `journal.view` | 返回附件元数据、撤销记录及当前期间是否允许修改。 |
| POST 前缀 | `journal.view` + `journal.attachment` | 以文件名、Base64 内容和依据新增附件。 |
| GET 前缀`/{attachment_id}` | `journal.view` | 返回原文字节；包含服务端摘要，禁止缓存和内联展示。 |
| POST 前缀`/{attachment_id}/reverse` | `journal.view` + `journal.attachment` | 以原因追加撤销记录。 |

管理员和财务员默认拥有 `journal.attachment`，可单独撤权；只读账号可核对并保存历史文件，但不能修改。找不到凭证或附件返回 404，无权限返回 403，格式或字段无效返回 422，期间锁定、超额、重复或重复撤销返回 409。写入在 ORM 会话的同一事务内核对，失败整体回滚。

桌面“总账凭证 → 详情”展示上传依据、操作者、时间、大小、撤销原因和保存入口。系统文件对话框选择上传与保存位置；渲染进程不获得文件路径或原文字节。主进程限制大小、固定接口路径和响应格式，会话变更后丢弃迟到结果。附件不自动关联银行流水、客户/供应商票据、采购或销售原单；这些业务单据的附件仍属于后续需求。

## 验证与限制

后端测试覆盖格式与摘要、权限、重复、并发、期间锁定、追加撤销、跨凭证访问及第 72 版升级保留旧凭证；桌面测试覆盖固定路径、字段白名单、响应校验和换号隔离。真实票据真实性、恶意文件扫描、容量规划以及 Windows/macOS 组合实机仍需部署验收。旧库升级不会推断或生成历史附件。
