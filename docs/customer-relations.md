# 客户关系与销售报价

第 50 版数据库在原客户主数据上增加联系人、跟进、商机、报价和审计；第 61 版增加客户负责人及归属变更历史，桌面入口为“销售管理 → 客户关系与报价”。业务读写全部使用 SQLAlchemy 声明式模型和 ORM 会话。适用边界为单公司、人民币、在线局域网。

## 客户负责人和可见范围

新客户默认由创建账号负责；旧客户没有可核验的归属，升级后保持未分配，不按既有联系人、商机或订单创建者猜测。管理员可在 CRM 页面选客户、启用账号及非空依据，按当前归属版本分配或转交。历史记录包含原负责人、新负责人、版本、操作账号、依据和时间；同负责人重复分配或旧版本返回 409，停用账号不能接手。转交立即改变现有客户及关联 CRM、销售订单、出库、退货和售后资料的可见范围，历史审计不改写。

持有 `crm.view` 的普通销售账号仅能读取自己负责客户的 CRM 资料；列表及选项均由服务端 ORM 过滤，猜测详情编号和变更记录也返回 404。CRM 写操作均在事务内校验客户归属。管理员及具备独立报价审核权的账号可以查看全部 CRM 客户，以便跨负责人审核。销售单据也按同一归属过滤普通账号；仓库和财务角色通过 `customer.view_all` 保留公司范围单据处理权限，但该权限本身不授予 CRM 联系资料读取权。旧客户分配前只对有全局查看权限的账号可见。

## 联系人和跟进

联系人必须属于已有客户。可修改姓名、职务、电话、邮箱、说明和启停状态；所属客户不可改，不提供硬删除。每次修订要求当前版本及原因，保留完整前后资料、账号和时间。停用联系人不可用于新建商机、跟进、报价或报价提交、批准、转单；已结束跟进和已提交报价的历史资料保留。

跟进记录所属客户、可选联系人和商机、负责人、事项、期限和安排。联系人和商机须属于该客户，负责人必须是启用账号。待办期限早于服务端北京时间业务日时标为逾期；同日不算逾期。完成或取消时填写实际结果或原因，原记录不可覆盖或重复结束；错误可取消待办后另建，结束后的更正另建跟进并引用原记录。系统不自动发送邮件、短信或通知，不证明已实际联系客户。

## 商机

商机记录客户、可选联系人、业务负责人、名称、预估金额、预计成交日及说明。开放阶段为初步接洽、需求明确、方案报价、商务洽谈；预估金额是人工估计，不计入订单、收入或收款，不自动推算成交概率。客户归属不可修改；商机和跟进的业务负责人字段不单独授予客户访问权，以客户主数据负责人及全局查看权限为准。阶段、金额和说明修订均要求当前版本与原因。

“已转单”只由批准报价转销售订单后在同一事务内登记，不允许人工把商机直接标为成交。待审核或已批准报价须先取消才能登记丢单；丢单原因保留在审计。已转单商机只有全部关联订单取消后才能填写原因重开，已丢单商机也通过重开回到初步接洽。原订单与报价保留，不复用原报价；再次成交须建立新报价。

## 报价和转单

1. 对开放商机建立唯一编号的报价草稿，指定可选联系人、有效期、商务条款及 1 至 100 行物料。客户从商机推导，客户端不能伪造客户、总金额、单据状态或订单内容。物料不能重复；数量为正、最多三位小数、不超过一百万；单价非负、最多四位小数、不超过十亿元。每行先按数量乘单价四舍五入到人民币分，再加总，不含税费、折扣或汇率计算。
2. 草稿和驳回单可按版本及原因修订，驳回修订恢复草稿、清空当前审核信息，但审计保留各次原单和所有历史参与者。提交时重新读取并冻结客户名称、联系人姓名/电话/邮箱、物料编码/名称/单位及数量、价格、条款。提交后的正文不可编辑；需要修改已批准报价时取消原报价另建。
3. 未参与任何一次创建、修订或提交的审核账号可批准或填写原因驳回。历史编制参与不会因再次提交或后续授予权限而消失。独立审核由服务端强制执行；默认销售员不能审核，管理员或显式授权的自定义角色可审核。
4. 批准后，持有报价转单及销售订单创建两项权限的人登记客户接受依据编号和原因，带报价版本及商机版本转单。服务端以冻结物料、数量及价格生成唯一销售订单草稿，并更新报价、商机和两份审计；任何步骤失败都整体回滚。重复或并发转单返回 409，同一商机的不同报价也不能同时生成两个有效订单。
5. 销售草稿仍按原销售模块确认、分批出库、退货及财务流程执行。转单自身不记库存、应收、收入或收款。报价只登记人工填写的客户接受依据，不自动验证合同效力或银行事实。

有效期按服务端北京时间业务日判断，当日仍有效。过期报价不能提交、批准或转单，仍可驳回或取消。草稿可修订有效期；已批准单须另建并重新审核。已转单报价不能取消或再次转单，即使销售订单后来取消。提交后联系人资料变更不改写冻结报价；联系人停用会阻止尚未转单报价批准/转单。报价物料有外键引用，不能从基础资料硬删除；后续名称修改不改变提交时快照，转出的销售单查询仍沿用既有基础资料名称。

## 接口和权限

统一前缀 `/api/v1/crm`：

| 接口 | 用途 | 权限 |
| --- | --- | --- |
| GET `/options`、`/overview` | 客户/物料/启用负责人及四类资料快照 | `crm.view` |
| GET `/records/{kind}/{id}`、`/changes` | 当前详情与完整历史，kind 为 contact/activity/opportunity/quote | `crm.view` |
| POST `/contacts`、PUT `/contacts/{id}` | 建立及修订联系人 | `crm_contact.manage` |
| POST `/activities`、POST `/activities/{id}/complete` 或 `/cancel` | 安排、完成或取消跟进 | `crm_activity.manage` |
| POST `/opportunities`、PUT `/opportunities/{id}`、POST `/{id}/reopen` | 商机阶段、资料及重开 | `crm_opportunity.manage` |
| POST `/quotes`、PUT `/quotes/{id}` | 草稿建立或修订 | `crm_quote.create` |
| POST `/quotes/{id}/submit` | 提交并冻结正文 | `crm_quote.submit` |
| POST `/quotes/{id}/approve` 或 `/reject` | 独立审核 | `crm_quote.review` |
| POST `/quotes/{id}/cancel` | 取消未转单报价 | `crm_quote.cancel` |
| POST `/quotes/{id}/convert` | 接受依据转销售草稿 | `crm_quote.convert` 和 `sales_order.create` |

客户主数据沿用 `/api/v1/customers`：新增客户使用 `customer.manage`；PUT `/{id}/owner` 带 `owner_id`、`version`、`reason`，GET `/{id}/owner-changes` 查看归属历史，均要求 `customer.assign`。`GET /customers` 仍要求 `sales.view`，返回当前账号可见客户的负责人及版本。

新增客户前，桌面端调用 `POST /api/v1/customers/duplicate-candidates`，只提交 1 至 120 字符的客户名称，要求 `customer.manage`。服务端通过 ORM 和现有客户归属范围筛选，仅返回可见客户中名称去大小写、空白和标点后相同的记录，或至少四字符的名称包含候选，最多 10 条、相同名称优先。界面提示编号和名称，用户核对后可再次提交；输入改动会重新查询。查询失败不跳过核对。此提示不写库、不自动合并、不证明两条客户属于同一法人；精确重名仍由原有数据库唯一约束返回 409。跨负责人且不可见的客户不通过候选接口泄露。

修订和动作输入带严格正整数 `version` 与非空 `reason`；转换另带 `opportunity_version` 和非空 `acceptance_reference`。未知或额外字段返回 422，记录不存在返回 404，状态、版本、重复编号和并发冲突返回 409。默认管理员拥有全部 CRM 操作，销售员拥有除审核外的操作；其他内置角色不自动获授私人联系信息查看权限。原客户新增仍使用 `/api/v1/customers` 的 `customer.manage` 权限，不建立第二套客户主数据。

桌面使用固定 IPC 白名单，清除表格行标记及任何客户端伪造状态。Pinia 保存草稿，换号或撤权清除敏感资料和表单；断线清除资料但保留同账号输入，恢复后重读。迟到详情/错误不能覆盖后打开记录，保存失败保留表单和操作依据。新建和修订在页内完成，审批/转单弹窗展示固定正文及依据。审计可查看修订前后资料和报价明细。

## 验证与限制

测试覆盖客户/联系人/商机匹配、负责人转交后撤权、CRM 与销售/出库/退货/售后的跨账号隔离、旧客户未分配迁移、停用账号和联系人、严格载荷、金额精度、历史作者审核保护、过期、版本竞争、不同报价并发转单、审计故障整体回滚、取消原单后重开、旧库升级幂等及失败回滚，以及桌面 IPC、权限、断线、换号和迟到响应。

本版提供联系人—跟进—商机—报价—销售草稿、客户负责人隔离及新增时相似客户提示，不等同于完整营销自动化。邮件发送、通知调度、附件、报价 PDF/外发、概率预测、客户去重合并、线索池、CRM 导入、税费和多币种仍未提供。
