# 损益结转规则

已实现单公司、人民币的损益结转草稿、独立审核过账、来源归档、原期间冲销和结账检查。数据库第 45 版新增 `profit_transfer_policies`、`profit_transfer_policy_changes`、`profit_transfers` 三张静态 SQLAlchemy ORM 表；旧库不补造历史结转。

## 公司科目范围

- 收入（`income`）、费用（`expense`）自动纳入，按实际借贷余额结转，不假定收入一定是贷方或费用一定是借方。
- 成本（`cost`）仅纳入公司明确选择的科目。销售成本可以纳管；生产成本及在制品不能未经业务核对直接作为损益清零。预览单独列出未纳管且有余额的成本科目。
- 本年利润须配置已启用、贷方正常方向的权益科目（`equity`）。这是公司科目映射，不自动创建法定科目表，不做利润分配或税额计算。
- 启用日期必须是开放期间的开始日期，初次保存后固定。配置修改携带版本和原因，前后范围、操作人及时间与主记录同一 ORM 事务保存。已有凭证保留生成时配置，新配置不会改写它。

## 金额与来源

预览读取已确认正式期初及截至目标期间末的全部已过账分录，使用 Decimal 累计精确分位。之前的有效结转与已过账冲销也计入，因此顺序结转时已清零历史不会重复记账。这是**累计待结余额**，不是本期利润表；首次启用时可能包含历史损益，须先核对。

每个纳管科目与完整辅助组合生成与当前余额相反的分录，逐个清零。借方余额用贷方抵销，贷方余额用借方抵销。盈利贷记本年利润，亏损借记；各科目非零但净额为零时仍生成清零分录，不生成零金额本年利润行；不同辅助组合分别转入本年利润，公司净额为零时仍可能有相抵的转入行。所有科目余额为零时无需新结转。单条金额须小于一万亿元；超限显式阻止，不截断或舍入。停用且有纳管余额的科目也阻止生成。

生成条件：期间已结束且开放，更早期间均已结账，截至期末的其他凭证已过账或取消，正式期初已处理，业务凭证纳管范围内来源均已有效过账。日期统一按服务端 UTC，凭证日期固定为目标期间结束日。

客户端只提交期间编号及版本、配置版本、来源指纹、依据编号和原因；金额、日期、分录及来源不由客户端覆盖。服务端在写事务内重算、验证、生成凭证与来源并保存创建审计。每个期间只能有一张有效结转；取消草稿或关联冲销过账后方可重建。配置、过账来源变化或过期预览返回 409；并发生成只允许一个成功。

生成快照包括损益余额、清零分录、转入科目、正式期初来源、凭证/分录编号、日期及借贷金额、配置范围和版本。后续科目改名不会改写快照，也不会使经济来源失效。

## 独立审核与更正

结转使用现有凭证的提交、独立审核、驳回、过账和取消权限，建单或提交过的账号持有当前步骤按钮权限时可审批自身凭证。生成草稿不能手工编辑，错误时取消后重建。提交、审核、过账前重验来源与配置；迟到凭证或新业务来源须先处理，失效草稿不能继续。

已过账结转通过统一 ORM 写事务保护来源：会改变其纳管历史分录的后续过账整体回滚，即使新增借贷净额相抵也不能绕过来源保护。普通资产分录、未纳管成本和后续期间分录不因本功能锁住。

结转冲销必须记入**原期间末**。已结账时先按倒序重开期间，再从较晚结转倒序冲销；冲销仍需独立审核过账，草稿冲销不解除来源保护。原凭证、来源及各次结账快照保留。解除保护后更正来源、重新生成和过账结转，再按顺序结账；不能跨期冲销历史结转后直接宣称原期损益已经清零。

## 结账检查

启用范围内的期间增加 `profit_transfer_pending`：纳管科目与完整辅助组合逐个期末余额必须为零，不能只比较净利润。未配置但已有收入/费用余额时也阻止结账，要求先明确范围。早于固定启用日期的旧期间沿用历史口径；未纳管成本保留，不作为清零条件。手工结转已清零的余额无需重复生成，结账证据会明确是否有有效生成结转。

结账归档增加当次配置、有效结转凭证号、残余与未纳管成本；旧归档没有此字段时继续可读。结账本身不自动建立或审核任何结转凭证。

## 权限与接口

独立权限 `profit_transfer.view`、`profit_transfer.configure`、`profit_transfer.generate` 默认授予管理员和财务员；查看不包含配置或生成能力。桌面入口在“总账凭证 → 损益结转”，页面入口还需要 `journal.view`；后端预览选项独立按结转查看权限提供，不要求科目维护权限。

统一前缀 `/api/v1/finance/profit-transfers`：GET `/policy`（配置、科目及期间选项）、GET `/policy/changes`（前后配置审计）、PUT `/policy`（版本和原因）、GET `/periods/{id}`（余额、来源、阻止事项、警告及当前结转）、POST `/generate`（仅生成草稿）。错误沿用 422 无效输入、403 越权、404 不存在、409 状态/版本/来源冲突。共享类型、固定 IPC 地址和 Pinia 动作同步维护；换号撤权清除旧快照，迟到读取不能覆盖新期间，保存失败保留输入。

## 验证与边界

后端测试覆盖盈利/亏损、净额为零逐项清零、成本范围、正式期初分位、过期预览、独立审核、手工修改拒绝、已过账来源锁定与回滚、同期间冲销和重开、跨期间倒序冲销、并发去重、审计故障原子回滚及旧库升级。桌面测试覆盖 IPC 白名单、切换期间、撤权、迟到响应、故障清理及失败输入保留。

公司财务报表、辅助核算与[历史分户期初](subledger-openings.md)由独立模块提供，结转保留完整辅助组合；利润分配、税额、多币种和银行对账尚未提供。真实公司科目、期初数据及会计样例仍须验收。
