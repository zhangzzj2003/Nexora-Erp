# 物料当前供需

仓库、采购的单据物料表及 MRP 的来源、手工需求、建议、日期结果共用“物料供需（全仓）”列。每行显示库存、计划中、待回料、待入库，点击查看数量来源和更新时间，可重新读取。当前供需独立于历史单据或 MRP 固定快照，不改变单据数量、审批内容、库存流水或业务写入规则。

## 数量口径

所有数量按物料基本单位展示，服务端在一个只读 ORM 事务中读取，以 Decimal 精确汇总至三位小数。统计范围固定为全部仓库，不代表当前单据指定仓库有同样数量；库存是账面结存，尚未扣除销售需求或生产待领需求，不能直接当作可用库存。

供需列、汇总卡片和来源明细仅在显示时去掉小数末尾多余的零，例如 `100.000` 显示 `100`、`1.500` 显示 `1.5`、`0.001` 仍显示 `0.001`。不取整，不改变接口精度、原始数量或业务计算。

| 项目 | 计入范围 |
| --- | --- |
| 库存 | 全仓已过账库存流水净额，包含追加式冲销；来源按仓库列出结存 |
| 计划中 | 当前可执行的最近有效已批准 MRP 采购建议、已批准采购申请未转单余额、MRP 转出的未取消申请余额，以及这些申请转出的未确认订单；独立批准但未确认的采购订单也计入 |
| 待回料 | 已确认或部分入库采购订单数量，减去未冲销的已入库数量，再减去已确认到货或已批准待入库的关联采购入库数量；不包含未确认采购订单 |
| 待入库 | 已确认合格收货自动生成、尚未过账的采购入库单；手工采购入库单须已批准，未批准的自由草稿不计入 |

MRP 的生产建议与生产预计产出不计入“计划中”；生产领料后待退回的“待退料”是独立业务口径。这里的待入库是采购供给阶段，不包含其他入库、生产完工或退料草稿。来源弹窗明确标识“当前采购供需”。

同一物料不同日期的建议在所选有效 MRP 方案内相加，同一批业务来源的不同 MRP 方案不能直接叠加。已过期、来源指纹变化或下游取消而不可转单的旧方案不计入。已转出的建议只沿下游原单统计；取消下游不会使旧建议重新计入。未批准的独立申请和订单草稿不计入，但从已批准 MRP 转出的待审批申请仍属于原采购计划，取消后移除。

采购申请转订单时，订单草稿占用的数量从申请余额扣除，并作为未确认订单继续计入计划，不能让拆单数量凭空消失。订单确认后转入待回料；合格收货确认后转入待入库；入库过账后转入库存。拒收不消除供应商交付义务，也不计入待入库。取消待入库单、冲销入库后，订单剩余交付量沿现有原单规则恢复；未核实的实物不能据此直接入库。

例如订单 1,000 件，确认两批合格收货 200 和 100 件，其中第一批已入库：本采购供给贡献为库存 200、待回料 700、待入库 100。任何收货与入库记录不能在两个阶段重复相加。

## 权限与读取边界

`POST /api/v1/inventory/material-supply/query` 接受唯一正安全整数列表 `material_ids`，每次 1～100 项，编号上限为 9,007,199,254,740,991，与桌面接口一致。未知编号、重复编号、布尔值、非整数、超大编号、额外字段或超量请求返回 422；未登录返回 401，没有任何相关查看权限返回 403。

库存、待回料和采购待入库沿用 `inventory.view`；完整计划汇总须同时具备 `inventory.view`、`purchase_request.view`、`mrp.view`。未授权数量返回 `null`，不查询对应领域、不返回来源，界面显示“无权限”。有权限且确实无数量才显示 `0`。

桌面主进程只允许固定接口和编号列表，响应校验检查物料身份、阶段、精确数量及来源合计守恒。Pinia 合并同一轮物料读取，最多 100 项一批；同物料短期缓存最多 15 秒，可见行共用一个 15 秒刷新时钟，关闭弹窗或离开页面释放订阅；点击来源或刷新会主动重读。业务快照变化、身份、服务端实例、权限或连接变化使结果失效；迟到响应不得恢复旧账号数据。失败不显示旧数量或伪零值，也不清空单据草稿。

## 验证

`backend/tests/test_material_supply.py` 覆盖计划转单、申请拆单、分批到货、拒收、入库及冲销、旧计划、跨仓小数、手工草稿、权限撤销和输入边界。`tests/material-supply.test.mjs` 覆盖 IPC、响应守恒、批量读取、错配、迟到响应、失效重读和草稿保留。界面预览为隔离示例数据，不能替代安装版 Electron 与已部署后端服务验收。
