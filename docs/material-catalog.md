# 电子生产物料档案与编码

已实现：物料管理沿用 `/workspace/catalog`，支持物料大类/子类、分类筛选、资料搜索、分页与供应商关联。新增窗口按基本资料、供应商绑定、电子参数、其他资料分组；旧物料可逐步补齐信息。

新增和编辑物料共用弹窗，桌面端最大宽度为 1200px，小窗口保留两侧各 16px 的边距。普通字段一行三列，分类和编码置于同一行；供应商绑定、环保要求、备注和修改原因保留整行。窗口宽度不超过 1000px 时改为两列，不超过 600px 时改为单列；内容较长时在弹窗内滚动。

## 分类与编号

分类目录由服务端 `GET /api/v1/material-categories` 提供，沿用 `inventory.view`。维护物料沿用 `catalog.manage`。本版分类为固定目录，不提供分类增删改管理页面。

| 大类 | 前缀 | 子类代码 |
| --- | --- | --- |
| 电子类 | EL | SR 贴片电阻、SC 贴片电容、TR 插件电阻、TC 插件电容、IC 集成电路、DI 二极管、TS 晶体管/MOS、IN 电感/磁性元件、CN 连接器、PC PCB、CR 晶振、SW 开关/继电器、WR 线材/线束、OT 其他 |
| 塑料类 | PL | HS 外壳、ST 结构件、OT 其他 |
| 五金类 | HW | FA 紧固件、ST 结构件、HS 散热件、OT 其他 |
| 包装类 | PK | OT 包装材料 |
| 其他类 | OT | OT 其他物料 |

编码格式为“大类-子类-六位流水”，例如 `EL-SR-000001`。各子类独立编号，正式编码只在保存时由服务端分配；窗口中的 `######` 是格式提示，不是预占编号。保存成功后列表显示实际编码。

分配与物料、审计在同一 ORM 写事务中完成，SQLite 写锁串行化并发新增。成功使用过的流水永久保留，删除物料不回收编码；事务失败不消耗编号。流水达到 999999 后返回 409，不扩大位数或回绕。

物料编码建立后固定。补充资料、调整分类都不改变编码；编码前缀表示建档时的类别，列表分类表示当前类别。分类调整会留下前后快照。被业务或库存引用的物料仍禁止删除。

## 详细资料与接口

名称、单位必填；新增必须选子类。规格型号、封装/外形、品牌/制造商、制造商料号、标称值/关键参数、精度/容差、额定电压、额定功率、工作温度、环保/合规要求、备注均为选填文本。参数保留单位和原始表述，例如 `10kΩ`、`±1%`、`50V`。本版不解析参数进行电气校验，也不提供自动去重或替代料判定。

`POST /api/v1/materials` 提交 `name`、`unit`、`category_code` 及详细字段，省略 `sku`。有分类时禁止手填编码。响应返回详细资料及 `version: 1`。

`PUT /api/v1/materials/{id}` 必须提交读取时的 `version`，成功后递增。过期或缺版本返回 409，重新打开编辑窗口读取最新版本后再修改。未提交的详细字段保留，显式空字符串清除字段。编辑窗口要求填写修改原因；旧调用方未填原因时，服务端记录“修改物料资料”。保存失败保持当前窗口与草稿。

`GET /api/v1/materials` 仍返回完整数组供各业务选择物料，增加详细字段和版本。库存、BOM、采购及销售单据继续按物料 ID 引用，简要物料契约不要求包含所有参数。客户端只允许固定路径，物料写入字段使用白名单；主进程核验资料与分类响应。

打开编辑器时通过 `GET /api/v1/materials/{id}?include_suppliers=true` 重新读取当前资料、版本及 `supplier_ids`；读取失败不打开窗口，退出账号、切换实例或断线后的迟到结果不更新快照。

`material_changes` 保存创建、编辑、删除的操作者、时间、原因及前后资料；删除后保留证据。本版没有变更历史查询界面。

## 供应商绑定与待完善档案

物料编辑器提供独立的“供应商绑定”框，品牌 / 制造商仍为单独字段。可搜索并多选已有供应商；输入新名称后按 Enter 添加到草稿。最多选择 20 家。取消、关闭或只输入名称均不会创建供应商；只有保存物料成功才创建并绑定。解除绑定不会删除供应商。

物料新增、编辑接口可提交 `suppliers` 数组，每项为 `{ "supplier_id": 现有编号 }` 或 `{ "name": "新名称" }`，两者不能同时出现。省略数组兼容旧调用并保留原关系；显式空数组清除全部绑定。新名称先按名称复用已有档案（ASCII 大小写不敏感，优先精确名称），旧库存在多个大小写同名项且无法确定时返回 409，要求选择编号。供应商创建、供货关系、物料版本、编码流水和审计共用 ORM 写事务；失败整体回滚。

供应商资料新增联系人、联系电话、电子邮箱、地址、税号、开户银行、银行账号和备注。`profile_status` 由服务端推导：联系人、联系电话、地址全部非空为 `complete`（已完善），否则为 `pending`（待完善供应商）；客户端不能自行设定状态。这表示联系资料的填写完整度，不代表采购审核或供应商资质认证。其余资料按实际情况补充。供应商管理显示状态并提供“完善资料”入口，可以分次保存；每次修改仍须读取当前版本、填写修改原因，审计保存完整前后资料。

单独绑定或解绑接口也递增物料版本并写审计，防止已打开的旧物料草稿覆盖其他页面的新绑定。供应商删除等导致已选档案不存在时，保存返回 404，草稿保留供重新选择。编辑详情未返回 `supplier_ids` 时，桌面提示升级服务并拒绝打开编辑器，避免误清除未知的供货关系。

## 升级与兼容边界

第 87 版新增独立的 `material_units` 单位表和 `material_unit_changes` 变更记录。基础资料下的“单位管理”支持搜索、状态筛选、分页、新增、版本编辑、启用 / 停用及最近 100 条变更查询。查看沿用 `inventory.view`，写入要求 `catalog.manage`；编辑必须携带版本和修改原因。

物料弹窗的单位改为可搜索的目录选择框。新增默认选择启用的“件”，否则选首个启用项；无可用单位时先到单位管理新增。停用单位不能用于新选择，原物料编辑仍可保留原单位；已被物料使用的单位不能改名，可以停用后建立新项，不提供删除操作。

升级预置常见计数、长度、重量和体积单位，并原样收录历史物料单位，不改历史数量、编码、版本或单据。新客户端提交 `unit_id` 与名称，由服务端核对当前目录及状态；旧 API 调用省略编号时仍兼容，未知单位在物料保存事务中收录，物料失败时一并回滚。单位目录与供货资料一样由 Pinia 快照共享；取消表单不写入。此功能维护单位名称，没有自动换算或多单位库存。

数据库第 54 版新增物料详细资料与版本列，以及 `material_code_sequences`、`material_changes` 两张静态 ORM 表，共 129 张。旧物料 ID、编码、名称、单位及关系不变，新增字段默认为空、版本为 1，不凭名称猜测分类。迁移从已有同格式编码初始化流水，避免后续自动分配冲突；重复启动不重复迁移。

客户端与服务端必须同步升级。新版编辑要求版本，旧客户端的无版本编辑会返回冲突；新版客户端发现服务端缺少详细字段或版本时提示升级。为既有接口与导入调用保留无分类、带 `sku` 的新增方式，桌面新增窗口统一自动编码。旧接口手填同格式编码也登记流水，删除后不会由系统重复分配。

第 86 版为供应商补充资料列，默认空字符串；保留原供应商编号、名称、版本、供货关系和历史审计，不猜测联系人等资料。旧供应商会显示“待完善供应商”，补齐资料后自动变为“已完善”。实际安装服务须升级并重启后才具备这些接口，不在启动时自动生成示例供应商。

## 业务选料资料

工作台的物料编号选择统一使用 `WorkspaceMaterialSelect`，复用公共下拉的搜索、键盘、必填和禁用行为。菜单第一行显示编码与名称，第二行显示规格、封装、品牌及制造商料号；多个搜索关键词可分别命中分类、规格和技术参数。调用方提供的候选范围、“全部”选项、禁用项和业务联动保持不变。

选中后默认显示分类、规格型号、封装、品牌、制造商料号与单位；展开后查看标称参数、公差、电压、功率、温度范围、合规信息和备注。空字段显示“未填写”；旧接口没有提供详细字段时显示“详细资料暂不可用”。资料卡是当前档案的只读展示，不承诺历史单据固定了这些参数，也不执行参数解析、替代料判断或单位换算。

报价、售后、设备维护、质检及库存预警的原业务读取接口附带统一的物料辨认字段及中文分类名称，沿用原接口权限，不额外调用库存物料管理接口。新增字段在主进程统一校验类型与长度，兼容只有编码、名称及单位的旧简要响应；不增加数据库迁移。

“其他入库”在表格内录入：点击添加立即新增空物料、数量为 1 的草稿行并聚焦选料框；其他行已选物料禁止重复选择，当前行允许重选。新增行后，之前的行只展示一行规格摘要与“查看资料”；每次仅一行显示完整资料，手动查看或重新选料会切换当前行。收起资料不改变物料和数量，移除当前查看行后默认查看剩余最后一行。空行可以继续填写或移除，保存前提示具体行号并阻止空明细、重复、失效物料和非法数量提交，最多 100 行。收起及保存失败保留完整草稿；成功保存清空明细，库存仍只在确认入库后增加。
