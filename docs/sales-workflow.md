# 销售单据与页面完善

销售订单、出库和退货沿用原单据及统一审批；本次新增草稿修订、金额核对、来源快捷操作、列表筛选和剩余交付终止。生产、采购流程仍由各自模块处理。

## 草稿修订

- `PUT /api/v1/sales-orders/{id}`、`PUT /api/v1/shipments/{id}`、`PUT /api/v1/sales-returns/{id}` 接收对应新建正文，并增加 `expected_version`（非负整数）和 `revision_reason`（1～200 字）。版本取列表响应的 `draft_version`，旧单和新建单从 0 开始。
- 修订沿用对应 `.create` 权限及客户可见范围。仅草稿允许修订，审批中和已批准单据须先撤回；已驳回或已撤回草稿修改后须重新审批。已确认单据继续通过原退货、冲销流程更正。
- 同一写事务核对版本、来源及数量，追加修改前后内容、操作人、时间和原因。审计写入失败时正文整体回滚；相同版本的两次并发修订仅允许一次成功。
- 相同来源的明细保留原 ID。修订不产生库存流水、应收或生产需求。出库确认和退货确认仍重新核对当前业务数量及库存。
- 报价转单草稿可补齐保修条款和调整订单明细，但保留原客户；原报价、合同历史和审批记录不重写。售后方案生成的换货订单、退货单仍从原售后流程更正，不能用普通草稿修订绕过方案。
- `GET /api/v1/sales-drafts/{document_type}/{document_id}/changes` 返回修订历史，类型限 `SalesOrder`、`Shipment`、`SalesReturn`，沿用 `sales.view` 及正文客户隔离。
- 数据库 v110 新增 `sales_draft_changes`。历史草稿不补造修订记录；订单、出库和退货响应的 `draft_edit_block_reason` 说明当前不可修订原因。

## 页面操作与设计

销售管理的列表与详情以已完成的生产计划、其他入库和基础资料页面为参照，复用 `WorkspaceTable`、`WorkspaceSearchFilters`、`WorkspaceSummaryFilters`、`AppStatusTag` 与公共单据弹窗，不建立另一套颜色或控件。

- 订单、出库和退货列表将编号、客户、金额、审批状态、业务状态、创建信息分列；列表保留紧凑物料摘要，完整数量、履约、保修及批次在详情表中按字段核对。编号与“查看”先打开业务详情，“单据审批”独立进入审批窗口；原批准、撤回、取消和冲销限制保持不变。
- 顶部概览按完整可见记录计数，可与关键词、客户和创建日期组合筛选。选概览时清除冲突的精确状态；重置恢复全部筛选。已冲销不计入已出库或已退货，终止剩余交付归入已结束订单。列表采用公共分页，筛选变化回到第一页。
- 联系人、跟进、商机、报价分别展示适用字段；电话与邮箱、金额与日期分别成列。列表操作集中为查看，修订、安排跟进、报价转单等放在详情。商机预测保留原计算口径，在列表下方展示。
- 售后来源和记录分开展示客户、物料、数量、方式和阶段，复用统一状态标签。售后详情采用分列资料面板；报价明细及维修耗材编辑复用公共表格。报价及售后长表单仅正文滚动，取消和保存固定在右下方。
- 订单可进入出库开单，已确认且未冲销的出库可进入退货开单；跨页开单和草稿修订使用副本，保留原先未保存的新单。修订记录按需读取。出库只允许订单内仍可交付且不重复的物料，显示订单剩余量和所选仓库存；缺货可保存草稿，最终确认仍由服务端复核。
- 金额汇总复用十进制金额工具，缺项不显示成零元；零单价提示人工核对。退货草稿明确显示预估金额，确认后显示固定结算金额。

页面布局可以用隔离示例数据验证；浏览器预览和构建通过不代表打包后的 Electron 或已安装服务完成验收。

## 退货金额

v110 同时给销售退货明细追加可空的 `settlement_amount`。新确认退货按原出库行累计退货数量计算应冲减金额，再减去既往有效退货金额，并限定在零到原出库剩余金额之间。确认金额与库存、审批执行同事务固定，冲销精确还原原金额。

例如原出库 2 件、单价 0.335 元，应收业务金额为 0.67 元，两次各退 1 件分别冲减 0.34 元和 0.33 元。全部退完后该出库行的销售业务净额归零；如果已收款，仍须另行登记实际退款。

草稿金额为预估，最终金额按确认时的有效退货重算。历史已确认单保留旧金额，不重算既有凭证；若历史退货已多冲减超过原出库额，禁止继续确认并要求核对更正。升级不会自动修复已经存在的历史尾差。

## 终止剩余交付

- 部分出库订单在详情使用“终止剩余交付”，填写原因并核对整单剩余数量。`POST /api/v1/sales-orders/{id}/close` 沿用 `sales_order.cancel` 权限及客户范围，正文为 `reason`（1～500 字）、`expected_lines: [{line_id, shipped_quantity}]`。事务内重核所有明细实绩，过期快照、重复终止均返回 409。
- v110 保留原表字段、编号索引、原有触发器和外键，扩展订单状态 CHECK，并增加可空 `closure_json`。成功后状态为 `closed`，剩余可出库量为零；原订单数量、价格、总额、出库和财务凭证不变。终止原因、人员、时间、当时逐行已出库量和终止量固定保存，数据库触发器禁止改写终止证据或重新打开状态。
- 有出库草稿、直接关联生产计划的未下达数量或未完工工单时拒绝终止。生产计划已取消但工单仍有效时仍拒绝。售后方案派生换货订单须从原售后流程处理。
- 对包含本订单需求的 MRP 汇总计划，检查已转换生产计划、工单和采购申请及其采购订单。存在未下达、未完工、未转采购订单或未收货数量时提示先处理原单；无法准确拆分汇总占用时保守拦截，不自动取消生产或采购单据。无精确来源关联的手工备货和采购不推断为该订单占用。
- 终止后不再进入新生产计划候选或 MRP 销售需求；旧 MRP 计算保留，但来源指纹改变后不能继续转单，须重算。已完成或已取消的关联任务保留历史。
- 已交付部分仍可通过原退货／冲销流程处理，实时实绩随之更新，终止时证据不变，订单不会自动恢复交付。此操作不登记退款，也不支持直接撤销；需要重新交付时另建订单。
