# 期间结账与历史成本锁定

已实现单公司、人民币的期间结账、倒序重开和历史证据归档。它固定已有总账与业务来源，不自动生成业务凭证、损益结转或法定财务报表。数据库第 43 版新增静态 ORM 表 `period_closings`，不猜测或补造旧期间的结账证据。

## 结账条件与时间口径

- 只能结已结束的期间，按时间顺序结账；结束日等于服务端 UTC 当日时仍不能结账。
- 截至期末的凭证必须全部过账或取消，包含期间之间空档日期的未处理凭证。期初、本期和期末借贷须平衡。
- 未处理的正式期初方案会阻止结账。没有正式期初的旧库可以按零起点累计结账，但检查面板明确提示，这不证明业务期初已核对。已结账后不能撤销该期间的正式期初。
- 截至期末的所有库存流水均须有金额依据，包括已被消耗的历史入库和出库；公司物料期末数量不能为负。检查按当时已知的有效核价、完工分摊重放移动平均。
- 历史应收应付无价来源显示警告并保留原证据，不用库存核价替代往来价格，不凭空补价。

手工凭证按 `journal_date` 归属；库存、业务来源及收付款按服务端保存的 UTC 发生/确认时间归属。日期范围包含期末全天，不能把界面本地显示日期当成业务归属日期。现有业务接口不提供回填历史发生日期。

## 操作与证据

会计期间页面提供结账检查、填写核对依据后结账、重开和结账记录。确认时服务端取得写锁，重新检查全部条件；客户端之前的检查结果不作为写入依据。请求携带严格正整数旧版本和非空原因。状态变化、版本递增、完整证据和期间审计在同一 ORM 写事务中提交；并发旧版本、校验失败或审计保存失败均不产生部分结账。

每次结账保存期初来源编号、总账余额、库存余额及金额流水来源、应收应付来源、收付款记录、订单间核销与截至期末的已过账凭证编号。归档内期间资料为操作前快照，结账记录的 `period_version` 为操作后的版本。它是当次证据，后续查询、改名、业务更正及重开不会覆盖它。

重开只允许从最近的已结期间开始，须有原结账证据。重开另存记录及原结账编号，不删除旧快照；更正后可以重新检查、结账，多次历史均保留。普通总账报表仍是实时读取，归档证据需从结账记录查看。

## 历史锁定边界

最近已结期间结束日及更早日期均锁定，包含期间空档，避免通过新增历史期间绕开结转余额。已结期间不允许建立/编辑/提交/审核/过账该日期的手工凭证，也不允许修改期间名称。

历史库存核价、领料人工核价、历史成本记录冲销以及对历史完工流水创建或冲销成本分摊均被拦截；已有结算来源依赖保护仍生效。需要回改历史成本时，先按倒序重开有关期间及处理结算依赖。

统一 ORM 写边界还检查新增库存、付款、核价、费用及结算记录的时间，防止时钟回退使新记录落入已锁日期；关联单据整体回滚。锁期后的当前业务仍可追加入出库、退货、冲销或付款等来源，原记录不被覆盖。已过账凭证可在未来开放期间建立关联冲销凭证，仍须独立审核和过账。

## 权限与接口

| 权限 | 用途 | 默认授权 |
| --- | --- | --- |
| `accounting_period.closing_view` | 检查摘要及完整归档业务证据 | 管理员、财务员 |
| `accounting_period.close` | 结账 | 管理员、财务员 |
| `accounting_period.reopen` | 重开 | 管理员 |

普通 `accounting_period.view` 只查看期间资料，不扩大为业务证据权限。自定义角色可以显式授予上述权限。页面读写还校验连接、权限和繁忙状态；切换账号、撤权或切换期间时不保留失效的证据请求。

统一前缀 `/api/v1/finance/accounting-periods`：

| 方法及路径 | 行为 |
| --- | --- |
| GET `/{id}/closing-check` | 返回阻止事项、来源编号、警告和汇总 |
| GET `/{id}/closings` | 返回各次结账与重开的归档记录 |
| POST `/{id}/close` | 传入 `version`、`reason`，重新检查后结账 |
| POST `/{id}/reopen` | 传入 `version`、`reason`，按倒序重开 |

无效输入返回 422，越权 403，不存在 404，状态、版本、锁期或检查冲突返回 409。`app/finance/period_closing.py` 装配接口，`app/core/period_lock.py` 与 ORM 会话提供历史日期保护。

## 验证与限制

测试覆盖顺序、结束日、未处理凭证、正式期初、缺价与期末截止、历史核价/完工分摊锁定、后期凭证冲销、并发版本冲突、审计故障整体回滚及旧库升级。页面使用独立临时数据库和模拟数据验证检查、结账、重开与旧快照保留。

[业务来源凭证](business-journals.md)已提供采购、销售成本及其他来源草稿生成；[损益结转](profit-transfers.md)、[公司财务报表](financial-statements.md)及[历史分户期初](subledger-openings.md)已另行提供；尚无在制及跨期成本报表或银行对账。借贷相等和成功结账不证明原始票据、科目选择或实物正确；当前验证不能替代业务方真实期初和会计样例验收。客户端和服务端须同步升级。

第 48 版结账证据的可选 `subledger` 字段保存已确认分户期初及截至期末的原单余额、资金快照。后续资金、改名或重开不覆盖旧证据；旧归档读取兼容。分户未确认或撤销后尚未重建时，凭证过账会被阻止；资金登记及追加冲销也受最后关闭期间日期保护。

第 44 版启用业务科目配置后，结账检查增加 `pending_business_sources`：启用范围内截至期间结束日的非零或缺价来源，须有当期结束前有效过账凭证；取消草稿、未过账及完全冲销均不能替代覆盖。未配置时保留原结账行为，详见 [业务来源凭证](business-journals.md)。

第 45 版增加 `profit_transfer_pending`：已启用范围内收入、费用及明确选择的成本科目须逐个期末清零；未配置但有收入/费用余额时也阻止结账。固定启用日期之前沿用历史范围，未纳管成本保留。归档增加当次结转范围、有效结转凭证编号及残余检查，旧证据继续可读。结转更正必须在原期间末，先倒序重开并倒序冲销结转，详见 [损益结转](profit-transfers.md)。

第 47 版结账证据保留辅助分录、期初的完整组合快照、未分配计数与科目规则；损益清零检查按科目和完整辅助组合进行，公司净额为零不能替代组合逐个清零。原结账快照不因档案改名或停用重写，详见 [辅助核算](auxiliary-accounting.md)。


售后归档固定截至期末最后一次方案审计、交接依据、客户物品保管数量、收费来源、有效工时成本和维修直接毛利依据，包含未交付维修；期末后的更正不会混入当期状态。无 `after_sales.cost` 权限时结账历史不返回工时成本及维修直接毛利。客户物品不计入公司库存金额。已结边界内的收费更正和新保管/审计记录受写事务锁期保护。见 [售后规则](after-sales.md)。
