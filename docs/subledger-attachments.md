# 历史原单票据附件（数据库 v100）

已提供历史应收、应付原单的文件留存、来源核对、原件下载及追加撤销。业务读写使用 `SubledgerAttachment`、`SubledgerAttachmentReversal` 两张静态 SQLAlchemy ORM 表；当前共 200 张模型表，31 类编号及审批单据保持不变。客户端与后端须一起升级。

## 文件与固定来源

- 支持非空 PDF、PNG、JPEG，按扩展名和内容标记核验，单文件不超过 5 MiB；保存原字节、文件名、媒体类型、字节数、SHA-256、上传依据及操作人/时间。
- 每张历史原单最多 10 个有效文件，相同原单不能重复留存相同摘要的有效文件。限额按同类、同对象和同原单号计算，改变科目或金额不能绕过；撤销后可重新上传。
- 附件绑定分户方案，保存上传时的原单编号、日期、对象、科目、借贷金额、完整辅助、人民币及期初依据。草稿保存重建原单行号时，原件和来源仍可查询；比较忽略临时行号、显示名称及辅助顺序。
- 原单金额、科目、日期、辅助或期初依据变化标记为“来源已变化”；原单移除标记为“原单已移除”。这些有效附件阻止送审、批准及确认，须追加撤销并按当前原单重新上传。旧来源、旧原件和更正理由永久保留。
- 上传和撤销必须携带刚读取的方案版本，服务端在写事务内检查，防止草稿重建或行号复用时把旧界面的文件绑定到另一张原单。并发上传的重复/限额核验与文件写入在同一事务内完成。

## 权限、审批与日期

读取沿用 `subledger_opening.view`；上传和撤销还需独立 `subledger_opening.attachment`。升级只给已有分户查看权的内置管理员/财务角色补齐写权，自定义角色须明确授权。跨方案下载及撤销返回不存在。

草稿或驳回方案可维护附件，期初生效日及当前服务端 UTC 日期都不能落入已结期间。执行或撤销审批处于送审/已批准状态时冻结全部文件操作。确认后可在当前开放日期补录证据，原批准附件不可撤销；后续补录文件可追加撤销。已取消或已冲销方案仅供查询与下载。

原批准正文包含确认前文件的固定来源、摘要、操作人与撤销事实，不包含原字节。确认后的补录不更改原批准正文、作者或摘要。v97 旧批准正文没有附件键，升级及补录保持该旧结构，不补写空键或推断旧原件。

两张表通过数据库约束禁止覆盖或删除，更正仅追加。写事务末尾还复核实际新增记录时间，防止预检后时钟回退把文件或撤销记录写入已结期间。

## 期间归档与备份

新期间结账证据增加 `subledger_attachments` 元数据，覆盖截至期末已上传的原单文件；撤销按自己的追加时间纳入同一截止日，不将后期撤销带回旧期间。不包含原字节、当前匹配状态或临时列表权限。既有 `PeriodClosing.snapshot_json` 不修改。在线备份和还原包含原字节、固定来源及撤销记录。

## 桌面与接口

在“分户方案 → 核对与审计 → 原单票据附件”查看附件。选择已保存的原单、填写依据后由主进程打开文件对话框；列表每页 50 条，服务端上限 100 条。界面可核对上传时的完整来源与 SHA-256，保存原件或填写原因追加撤销。原批准附件不显示撤销操作。

| 接口 | 作用 |
| --- | --- |
| `GET /api/v1/finance/subledger-openings/{id}/attachments?page=1&page_size=50` | 当前方案版本、可维护状态、原单选项、来源变化摘要和分页文件元数据 |
| `POST /api/v1/finance/subledger-openings/{id}/attachments` | `opening_version`、`line_id`、`file_name`、`content_base64`、`reason`；固定来源并保存原件 |
| `GET /api/v1/finance/subledger-openings/{id}/attachments/{attachment_id}` | 返回核对长度与摘要后的原字节，禁止缓存，提供摘要及扩展名响应头 |
| `POST /api/v1/finance/subledger-openings/{id}/attachments/{attachment_id}/reverse` | `opening_version`、`reason`；追加撤销证据 |

IPC 使用固定路径与白名单参数，列表及写入响应核对方案、来源、分页、摘要与状态；文件字节及本地路径不进入生产渲染层。实例、证书、账号、角色、权限、断开后重连或方案变化均使在途结果失效。

此能力提供人工上传证据，不包含票据真实性/电子签名验证、OCR、病毒扫描、发票税务处理或自动匹配。
