# 设备维护规则与开发状态

设备维护已提供静态 ORM 后端、版本迁移、独立权限、桌面 IPC、Pinia 草稿、设备台账、日历与运行小时保养计划、维护工单页面和审计展示。运行小时能力基于人工登记的表计读数；构建与临时数据库浏览器检查不等同于业务方或实机验收。

沿用单公司、人民币、在线服务端边界。声明外委费用不等同于应付或付款，不自动生成总账凭证、固定资产折旧或生产成本分摊。自动采集遥测、附件、维修采购、有限产能排产及完整资产财务管理仍待实现。

## 台账与计划

设备包括唯一的大写编号、名称、位置、可选唯一序列号及启用/停用/报废状态。空序列号存为 null，输入和详情使用空文本。有未结束工单时不能改绑编号或序列号；停用或报废前须结束未完成工单并停用全部日历及运行小时计划。报废设备不能重新启用，历史档案不删除。

日历计划属于一台设备，记录唯一编号、维护事项、1–3650 天间隔、下次到期日和启用状态。日期按 UTC 日历日，范围 2000–2099 年；未来计划可以先编草稿，到期才能提交。没有后台自动建单或消息调度。

同一计划的同一到期日只能由一张未取消、未更正工单占用，草稿也占用。有未结束关联工单时不能修订计划。成功验收将到期日推进到验收登记日加间隔天数，并增加版本、追加计划审计。

运行小时读数由有 `equipment.meter` 权限的账号按设备登记，保留依据编号、原因、登记人、前一笔读数及更正标记；同一设备的依据编号不可重复，读数不覆盖旧记录。常规读数不能倒退；错误读数由同时具备 `equipment.manage` 的人员追加更正。写入时必须提交最新读数编号，来源变化返回 409。只允许启用设备登记，数值使用最多两位小数的十进制文本，不接受浮点数。

建立运行小时计划前必须先登记表计基线。计划记录唯一编号、维护事项、间隔小时、下次到期小时、启用状态和修订版本。当前读数达到阈值时，页面显示到期并允许提交工单；没有自动建单或后台遥测调度。每个计划阈值只允许一张有效工单占用，草稿也占用；关联工单未结束时不能修订计划。成功验收将阈值推进到“当前读数与原阈值中的较大值 + 间隔小时”，保留推进前后审计，避免过期多轮重复建单。

## 执行及独立处理

故障维护不关联计划；周期维护必须且只能关联一项启用、属于同一设备的日历或运行小时计划。工单保存设备、计划版本及到期日或小时阈值、编制时的读数编号、可选生产工单、指定执行人、维护说明和耗材。保存或修订草稿时记录设备与生产来源快照，旧修订保留在审计中。小时工单在提交、审核及开始时重新核对当前读数已到阈值；开始后的报工和验收保留已经发生的证据，不因后来追加的读数更正而抹去执行记录。

状态流程：草稿/驳回 → 提交 → 独立审核 → 开始维护 → 报工 → 独立验收。驳回后允许修订并重新提交。复检要求返工时回到执行中，再次报工，保留每次处理结果、工时、声明费用及依据。

编制、编辑或提交过该工单的人不能审核自己参与的工单；这些人员、指定执行人和报工人也不能验收或要求返工。管理员同样不能自审。审核人可以承担后续独立验收，不强制第三个账号。开始及报工只允许当前指定、启用且有执行权限的账号；报工后执行人停用不使已经登记的报工证据失效，仍可独立验收。

开始维护时在同一事务中登记一条服务端时间的停机区间，同一设备不能有重叠的执行中/待验收工单。复检返工沿用未结束区间，验收或取消时记录结束时间、人员及依据。查询的开放时长会自然增长，这是系统登记的区间，不是遥测或补录历史故障时间。

生产工单关联仅用于追溯影响，不改变生产数量、排产或成本。编制、提交、审核和开始时检查原工单未取消；已经开始的维护允许在生产工单后来取消后继续如实报工、验收，并提供原快照和当前状态。没有 `production.view` 时隐藏关联编号、快照及审计中的生产来源，不能用修订接口清除隐藏关联。

## 耗材与声明费用

耗材数量须为正数、最多三位小数且不超过一百万，物料不能重复；有耗材必须指定仓库，无耗材不能指定仓库。开始维护只生成唯一“其他出库”草稿，不扣库存；执行人还须有 `other_outbound.create`。确认、余额校验、移动平均计价、锁期及冲销由现有仓库模块处理。

报工和验收都要求关联出库有效确认；已冲销出库不能支持验收。有效维护验收使用的出库禁止直接冲销，先更正验收。取消维护前须取消尚未领用的出库草稿；已实际确认领用的库存流水保留，取消维护不能冒充实物归库。实际归库另办原出库冲销。

未报工的工时和声明外委金额为 null；报工必须显式填写，无外委或免费也须填零。工时非负且不超过十万小时，费用非负且不超过十亿元，均最多两位小数，使用 Decimal 和精确文本。声明费用按设备维护查看权限展示，不等同于正式应付，不把耗材缺价当零，也不提供完整维护总成本或自动凭证。

## 更正及事务

未验收工单可以取消；已验收只能追加更正，不能改写原报工或抹掉已登记停机。更正不自动归库、重新停机或撤销财务凭证。

若验收推进后的日历或小时计划未再变化，且没有后续有效关联工单，更正恢复原到期日或小时阈值并追加对应计划审计，返回 `plan_roll.reversal_effect=restored_due`。已有更新的计划修订或后续工单时保留新计划，明确返回 `retained_newer_schedule`；必要时由有权限的人另行登记计划修订，不能用旧验收覆盖新的决定。

所有修订和动作须带严格正整数版本。过期版本、重复处理或来源变化返回 409；未授权 403、未登录 401、格式或精度错误 422。写入统一 ORM 会话，核对前取得 SQLite 写锁；来源关联、耗材草稿、停机、计划推进及审计整体提交或回滚。数据库唯一索引另外约束计划到期占用及执行中设备，不删除原数据。

## API 与权限

路由、输入和规则位于 `app/production/equipment.py`、`equipment_inputs.py`、`equipment_rules.py`，前缀 `/api/v1/equipment`。

| 接口 | 内容 |
| --- | --- |
| `GET /overview` | 同一读取快照的台账、日历及小时计划、工单摘要和受限选项 |
| `GET /assets/{id}`、`POST /assets`、`PUT /assets/{id}` | 设备详情、建立、带版本修订 |
| `GET /plans/{id}`、`POST /plans`、`PUT /plans/{id}` | 计划详情、建立、带版本修订 |
| `GET /meter-readings?equipment_id=...`、`POST /meter-readings` | 按设备查看与追加运行小时读数 |
| `GET /hour-plans/{id}`、`POST /hour-plans`、`PUT /hour-plans/{id}` | 小时计划详情、建立、带版本修订 |
| `GET /jobs/{id}`、`POST /jobs`、`PUT /jobs/{id}` | 工单证据、草稿、带版本修订 |
| `POST /jobs/{id}/{action}` | submit、approve、reject、start、report、rework、accept、cancel、reverse |

动作必须填写版本、原因和证据；只有 report 接受且必须包含 solution、labor_hours、service_amount。写入同时需要查看权限和相应操作权限，建立或修订生产关联另需 `production.view`。执行人选项只查询并返回启用且有执行权限的账号编号与用户名，不返回人员联系方式或完整角色资料。

十项权限为 `equipment.view/manage/meter/create/submit/review/execute/accept/cancel/reverse`。管理员默认全部拥有；计划员默认查看、台账/计划维护、表计登记、编制、提交、执行、取消；仓库员默认查看、表计登记、执行。读数更正还要求 `equipment.manage`。独立审核、验收、工单更正默认仅管理员拥有，也可明确授予自定义角色；执行权限不能替代指定执行人约束。

第 53 版新增设备台账、日历计划、维护工单、停机及变更审计五张静态 ORM 表；第 63 版新增运行小时读数、小时计划和计划审计三张表，并扩展维护工单来源字段；第 64 版增加售后维修工时表，第 65 版增加商机概率列，当前总计 147 张。迁移只追加结构和权限，不重写原采购、库存、销售、生产、财务数据，不使用运行时反射或 create_all。

## 桌面入口与验证

`/workspace/equipment-maintenance` 在生产管理中使用独立 `equipment.view` 入口。`EquipmentMaintenanceView.vue` 提供维护工单、设备台账、日历计划和运行小时计划；`EquipmentEditor.vue` 页内编制资料与表计读数，`EquipmentEvidence.vue` 显示读数、计划修订、停机、耗材来源及中文前后差异。阶段确认弹窗先读取当前版本，操作必须填写原因和依据；报工工时与费用初始为空，零须明确填写。

共享业务数据使用 `equipment-api.ts`；主进程只允许固定操作、字段白名单、严格编号和固定动作，并用 `equipment-validation.ts` 校验返回的阶段、精确数值、动作、来源和审计形状。耗材界面行标记不会写回服务端。预加载继续通过既有受限 `erp:call` 桥接，不暴露 SQL、文件或任意路径。

Pinia `equipment-actions.ts` 保留跨页面草稿与修订版本。读取失败隐藏旧快照；同账号断线保留输入，换号或权限变化清除旧数据和草稿，迟到读取/保存不会覆盖新会话。保存冲突保留旧版本与本次正文，须返回记录读取最新证据后重新修订，不自动覆盖。只读账号没有建改或阶段动作，撤销查看授权隐藏整页。停用计划仍可修订其非启用设备关联，启用时由服务端重新检查设备有效性。

浏览器以独立临时数据库的明确模拟数据检查浅色 1440、深色 960 和实际桌面视口，宽表内部横向滚动；覆盖建档、日历/工单编制、独立验收、耗材经仓库确认、明确零值报工、只读/无权、断线、读取失败和版本冲突。单元测试覆盖 IPC 白名单、非法动作/编号/浮点、响应形状、迟到会话、保留草稿、位置必填与未报工金额；Naive UI 门户控件的交互由浏览器检查，不由 SSR 模板测试代替。
