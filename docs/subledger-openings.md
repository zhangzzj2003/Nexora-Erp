# 历史未结单据分户期初

本模块用于单公司、人民币首次启用：逐客户或供应商录入启用日前的历史未结单据，并与已确认总账期初逐控制科目和完整辅助组合勾稽。导入明细独立保存，不伪造采购/销售订单，不再次增加总账余额，也不加入现有订单的应收应付汇总。

## 启用与核对

- 先独立审核并确认正式总账期初。分户方案绑定该方案编号与版本，启用日沿用其日期，不能由客户端另设。
- 创建、修改、提交、批准、确认时，库内不得已有已过账凭证、业务往来来源或订单收付款记录。业务往来来源指已确认采购入库、采购退货、销售出库、销售退货及各自冲销形成的应收应付来源；即使金额尚未核价、来源净额为零或订单资金已经冲销也不能绕过首次启用限制。旧库不自动推断或回填历史欠款。
- 每类往来选择一个启用的资产/负债控制科目，客户应收与供应商应付不能共用科目。最多两个控制范围；已配置的业务凭证应收/应付用途必须使用同一科目。有效分户方案存在时，配置不得把对应用途切换到其他科目。
- 每笔原单日期必须严格早于启用日；客户/供应商须存在，附加维度仅接受部门和项目，名称与编码由服务端解析。每行只填借或贷一方正金额，精确到人民币分位。最多 500 笔；同类别、同对象、同原单编号不能通过改科目或项目重复导入。
- 按所选控制科目以及客户/供应商、部门、项目的**完整组合**比较借减贷净额。所选总账科目的全部组合都参与，包含没有明确往来对象的余额；不能仅以公司合计相等替代逐组合一致。未指定往来对象的总账余额须先更正正式期初。
- 对应控制范围全部为零时允许空明细，仍须提交、独立审核和确认。借贷相抵仅发生在同一完整组合内，原始各笔正负余额仍分别保留。

阶段为草稿 → 送审 → 按固定模板逐步独立审核、核准及批准 → 确认。`SubledgerOpening` 模板支持一至五步，编制、编辑或提交人员及管理员持有当前步骤按钮权限即可审批；同一人可完成多个已授权步骤。审批依据必填且最多二百字。草稿/驳回可修改并增加版本；正在审批或已批准须先撤回，才能取消草稿。旧送审、批准和驳回接口返回 409，旧已批准但未启用方案须重新取得统一批准。

送审固定完整五百笔原单、往来与辅助身份、控制科目及绑定的总账期初正文和版本；基础资料名称不改变组合身份。审批弹窗展示前一百笔并明确提供“核对与审计”全文入口，全部原单参与正文校验。确认仍逐组合重核，并将固定核对结果、原业务审计及审批执行事件在同一 ORM 事务提交，失败整体回滚。

同一时间只能有一个有效方案。撤销另行送审，固定原确认人员、时间与撤销原因，原确认人、编制人员及撤销申请人按当前步骤按钮权限审批。全部批准后仍须核对尚无过账凭证、期间未关闭且从未执行该方案的分户资金；资金即使已经冲销仍不能重设期初。原金额、明细、核对证据与启用批准保留；旧已确认方案供历史查询，不补造审批。有效分户方案阻止撤销其正式总账期初。分户尚未确认或曾撤销且尚未重新确认时，凭证过账与订单资金写入会被阻止。首次启用条件、版本、唯一性及写锁共同防止并发重复启用。

## 余额、资金与凭证

客户未结金额按借减贷计算，供应商按贷减借计算；正数为待收/待付，负数为可退款/可收供应商退款。金额计算全部使用 Decimal，模型以文本精确保存。

确认后可以对每笔历史单据保存正金额收款/付款或退款草稿，先按当前余额检查可登记金额；`SubledgerPayment` 固定历史原单、控制科目、完整辅助归属、金额、参考号和依据，按角色按钮权限完成一至五步批准后才能执行。草稿和批准不影响余额，也不预占资金；执行在原写锁内按**执行时最新未结金额**重新检查方向、限额、有效分户方案和期间。所查历史截止日余额仅供参考。未取消的同原单同动作参考号不得重复；取消草稿保留记录和编号且释放参考号。保存及实际执行时间分别记录，不能倒签，真正执行不得进入已关闭期间或早于启用日。

反向操作保存等额草稿并取得新单号，固定原执行事实，原记录保留；须另行独立批准后执行。原建单人、原执行人及反向申请人持有当前步骤按钮权限时可批准反向资金，从提交到执行均要求冲销权限。有效反向草稿占用原单冲销入口，取消后可以重新申请；反向资金不能再次反向。执行检查原资金日期和当前期间，状态、执行时间、版本和追加审批事件同事务提交，失败整体回滚。

每笔已执行资金作为 `subledger_payment:<id>` 业务凭证来源，由业务科目配置的现金与应收/应付用途生成草稿，再独立审核过账。生成默认带入原单的真实往来及全部部门/项目快照，不能改换或新增归属。资金冲销不直接冲销已过账凭证，仍须按已有业务来源更正规则处理；该范围启用业务凭证后，未完成的来源处理会阻止结账。人工登记不能证明银行实际入账。

余额查询的截止日含当日全部 UTC 已执行资金，按实际执行日期计算，支持类别和对象过滤；所有导入单据都保留，已结清行仍显示零未结。返回原单、逐笔资金、期初、资金净额、未结、合计和同快照 CSV。CSV 处理公式前缀；筛选变化、换号、撤权或断线使旧结果失效。资金列表显示本地时间，查询与 CSV 明确按 UTC 截止日。

结账证据新增当次确认方案及截至期末的分户余额与资金快照；后续登记、档案改名或重开不会重写旧归档。旧结账证据没有该字段，读取兼容保留。只读核对已关闭期间不触发写入锁。

## 接口与授权

基路径 `/api/v1/finance/subledger-openings`。

| 方法与相对路径 | 权限 | 作用 |
| --- | --- | --- |
| GET 基路径、`/{id}/check`、`/{id}/changes` | `subledger_opening.view` | 方案、逐组合核对、完整审计 |
| GET `/options` | `subledger_opening.create` | 正式期初、可选科目、辅助档案与规则 |
| POST 基路径、PUT `/{id}` | `subledger_opening.create` | 建立、按版本修改草稿 |
| POST `/{id}/submit`、`/{id}/approve`、`/{id}/reject` | 原对应权限 | 旧客户端入口返回 409，使用统一审批 |
| POST `/{id}/confirm` | `subledger_opening.confirm` | 确认启用 |
| POST `/{id}/cancel`、`/{id}/reverse` | 对应 `subledger_opening.cancel`、`subledger_opening.reverse` | 取消、受限制撤销 |
| GET `/payments`、POST `/query` | `subledger_opening.view` | 资金历史、截至日期的未结余额与 CSV |
| POST `/lines/{id}/payments` | `finance.record` | 保存收款/付款或退款草稿 |
| POST `/payments/{id}/reverse` | `finance.reverse` | 保存独立反向草稿 |
| POST `/payments/{id}/post`、`/payments/{id}/cancel` | 普通资金 `finance.record`，反向资金 `finance.reverse` | 批准后执行、先撤回后取消 |

管理员与财务员默认拥有七个独立分户权限，职责分离仍生效。资金审核另要求 `finance.review`，可通过自定义角色授权独立审核人员，登记权限不能代替审核权限。只读权限不授予建单选项、编辑或资金写入。状态动作须提供当前版本和原因，资金须提供金额、参考号和原因；路径编号必须为正整数。错误金额、日期及额外字段返回 422，状态、余额、重复、组合或版本冲突返回 409，无权限返回 403。

统一入口为 `/api/v1/system/document-approvals/SubledgerOpening/{id}`，读取及 `submit|approve|reject|withdraw` 按审批版本和 `intent: execute|reverse` 操作；原送审、审核权限保留，撤销送审及执行要求 `subledger_opening.reverse`。启用执行保持原 `confirm` 路径及业务版本；撤销执行原因只读且须与独立批准原因相同。换服务端、账号或权限使旧操作弹窗与排队写入失效。

桌面入口为“财务管理 → 分户期初”，地址 `/workspace/subledger-openings`。页面提供未结余额、分户方案、资金记录和原单核销四种工作模式；详情先显示组合差额，再显示原单和审计前后快照。固定 IPC 只转发明确字段，Pinia 管理共享状态；失败保留输入，同账号断线保留草稿，换号或撤权清理。窄窗在表格内部滚动，不把历史原单映射为现有订单。

## 升级、验证与边界

数据库第 48 版增加 `subledger_openings`、`subledger_opening_lines`、`subledger_opening_changes`、`subledger_payments` 四张静态 ORM 模型表，全部业务读写使用统一会话。迁移不生成期初或资金，不改变旧总账金额；客户端与服务端须同步升级。

测试覆盖逐组合与公司净额差异、真实往来及日期/金额校验、独立审核、版本及并发限额、超额/退款/冲销、创建/确认/资金失败回滚、历史查询、凭证来源与固定辅助、期间锁定及旧归档、CSV、只读授权和第 47 版原子升级。桌面回归覆盖固定地址、字段白名单、控件内部字段剔除、迟到响应、断线草稿、换号撤权和独立入口；浏览器验收使用独立临时数据库和明确标注的模拟数据。

当前只处理一次首次启用的历史应收应付未结明细；不含运行中补导、同一往来类别的多个控制科目、历史原单与现有订单之间核销、跨辅助组合或控制科目的转账、票据附件、银行流水联查、税费、多币种、现金流量、固定资产或实物期初计价。不能用成功启用替代业务方真实期初及科目样例验收。既有订单余额与历史分户单据分别查询，详见 [业务凭证](business-journals.md)、[正式期初](opening-balances.md)与[期间结账](period-closing.md)。

第 91 版为历史资金补充已执行状态与原人员/原时间，不改变原金额、编号、外部参考、辅助归属和经济指纹，也不补造审批。资金审批沿用 `/api/v1/system/document-approvals/SubledgerPayment/{id}` 及审批版本、`intent: execute`；已执行历史只读显示原事实。桌面资金记录提供资金审批、批准后的确认资金、取消草稿及建立独立反向草稿入口，批准或业务版本变化、实例/证书/账号/权限变化会使旧弹窗失效。


## 历史原单核销（数据库 v96）

历史贷方原单可抵扣另一张待结原单。双方必须来自同一有效已确认分户方案，并具有相同应收/应付类别、客户/供应商、控制科目及完整部门/项目组合；辅助顺序和显示名称不改变身份。同一原单不能自抵销。单公司、人民币规则继续生效；跨归属转账及历史原单与现有订单之间的核销仍待另行实现。

第 96 版新增静态 ORM 模型 `SubledgerSettlement`，自动取得 `LSHX` / `SLS` 单号，并纳入统一审批模板。迁移只增加空表、索引和默认模板，不更改期初、资金、既有审批或总账金额；当前共 196 张模型表、30 类编号及审批单据。既有编号设置原样沿用，不要求再次配置。

`GET /api/v1/finance/subledger-settlements` 沿用 `subledger_opening.view`。POST 基路径按 `finance.record` 保存草稿，仅接受严格正整数 `from_line_id`、`to_line_id`、最多两位小数的正金额 `amount`、参考号 `reference` 和二百字以内 `reason`。保存、送审、批准和执行均核对当前余额及有效方案；草稿与批准不改变或预占余额。

统一审批 `/api/v1/system/document-approvals/SubledgerSettlement/{id}` 固定双方完整原单、金额、参考、核销依据和原核销记录，使用一至五步模板及 `finance.review|verify|approve` 按钮权限。持有步骤权限的编制人员可审批，业务登记权限不能代替审批授权。`POST /{id}/post|cancel` 需要当前业务版本和必填依据；执行须完整批准，在同一 ORM 写事务内复核最新贷方及待结限额，追加审批执行事件，故障整体回滚。待审或批准草稿先撤回再取消，取消保留单号但释放参考号占用。

执行后，来源原单的核销净额为负，目标原单为正；`未结 = 期初 - 资金净额 - 核销净额`。同一组合两端净额为零，不新增银行资金记录或业务凭证来源。报表、CSV 及原单来源详情分别展示资金与核销，按实际执行 UTC 日期取截至余额；期间结账固定核销记录及余额，旧归档不回填。

`POST /{id}/reverse` 按 `finance.reverse` 保存等额反向草稿，重新批准后执行才恢复双方余额；反向的送审和执行也要求该权限。原核销不改写，禁止重复反向及反向再反向；取消的反向草稿释放申请占用，新申请使用新单号。原核销日期处于锁期时拒绝更正，须倒序重开相关期间。存在未取消核销草稿或任何已执行核销的期初不能撤销，即使核销已反向执行也保留历史来源。

桌面“原单核销”可读取今日全部原单，选择同一完整归属的贷方与待结原单，保存、审批、执行、取消及反向更正；筛选日余额只作选择依据，超额在服务端拒绝。失败保留输入；换实例、证书、账号、角色或权限清理旧弹窗，排队写入复核原会话；确认时同时核对业务和审批版本。测试覆盖应收/应付、双边归零、截至余额、实际页面、只读权限、并发限额、资金变化、正文变化、锁期归档、审计失败回滚及 v95 升级失败回滚与重放。

隔离示例数据库的真实页面与后端已验证：保存 30.50 元草稿，送审及批准后余额保持不变；执行后 200.00 / -50.00 元分别成为 169.50 / -19.50 元，资金净额仍为零；另建等额反向草稿，独立批准执行后恢复原余额，正反单号及审批事件保留。重新加载后的页面无控制台错误；此验证不替代已安装服务升级和真实业务验收。
