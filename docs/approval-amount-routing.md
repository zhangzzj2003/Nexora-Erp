# 审批金额条件分支

本功能适用于当前单公司、人民币实例。管理员在原“单据审批步骤”中为支持金额的单据配置区间和步骤；系统不预设业务金额门槛，也不自动授予任何审批权限。

## 区间与步骤

- 每类单据保留一至五个默认步骤，另可配置最多五个金额分支，每个分支同样有一至五个步骤。
- 分支名称须唯一，金额区间不能重叠。下限包含、上限不包含，上限为空表示不设上限；相邻区间可以共用一个界限。
- 金额与界限均用十进制文本保存，精确到分，不使用浮点数选择分支。界限最多为 1,000,000,000,000,000,000 元。
- 正常送审时，命中区间就使用该分支的完整步骤；未命中时使用默认步骤。不存在空流程或自动批准路径。
- `intent=reverse` 的冲销、撤销申请始终使用默认步骤，不套用原经济金额的分支。退款以及以新单据办理的反向收付款、反向核销及反向转账，按该新单据自身金额的绝对值选择分支；原正文和业务余额仍保留原符号。
- 所有步骤继续按审核、核准、批准按钮权限办理；金额分支不会扩大单据可见范围、略过领域前置检查或代替批准后的业务执行。

## 金额依据

金额只从服务端在原事务内生成的审批正文取值，客户端不能提交命中结果或替代金额。

| 单据 | 固定金额口径 |
| --- | --- |
| 采购申请、采购订单 | 逐行金额合计。总价模式使用原始行总价，单价模式逐行四舍五入到分后相加。 |
| 销售订单、CRM 报价 | 数量乘单价，逐行四舍五入到分后合计。 |
| 总账凭证 | 借方合计，借贷两侧不重复相加。 |
| 完工成本结算 | 已固定结算计划的总成本。 |
| 订单收付款、历史原单收付款 | 本单金额绝对值。 |
| 订单间核销、历史原单间核销、历史与订单核销、跨组合往来转账 | 本单金额绝对值。 |

以上共十二类。没有金额正文的仓库、数量或计划类单据不开放金额分支，也不为路由而额外读取受限财务数据。采购申请允许未定价，但模板启用金额分支后，缺少任一行价格就拒绝送审；未知金额不当作零、不落入默认步骤。未配置金额分支时继续使用原流程。

## 固定与更正

送审在同一 ORM 写事务中保存模板版本、实际步骤、金额口径、金额、命中区间及当时完整分支规则。审批事件追加保存这些证据，不改变原业务正文的指纹。后来修改价格、数量等正文仍会触发原内容冲突检查；后来修改模板不会改变已送审或已批准单据的步骤。

撤回或驳回后重新送审，使用当时最新的模板和正文重新选择分支。原轮次事件和命中证据保留，审批进度切换轮次时显示各自的原依据。模板修改同样保留前后步骤和分支，并校验递增版本；冲突时前端保留输入，须显式载入新版本。

## 接口与升级

现有模板 GET 增加 `branches` 和可空的 `amount_basis`；管理员 PUT 在原 `version`、`steps` 外增加可选 `branches`。每个分支包含 `name`、`min_amount`、可空的 `max_amount` 和 `steps`。显式空数组表示删除全部金额分支，`null` 不合法。旧客户端省略分支时可保存原无分支模板；已有金额分支时拒绝这种保存，防止旧客户端静默抹去条件。

审批状态和历史事件可带 `routing`，其中包含 `mode`、`basis`、可空的 `amount` 和可空的 `branch`。数据库保存完整规则，普通状态响应只提供本单命中证据；不向客户端暴露或接收可改写的审批正文。

数据库 v112 仅给原模板追加默认空数组的 `branches_json`，给审批实例追加可空的 `routing_json`；不改写旧正文、编号、人员、步骤或历史事件，不补造旧单据的金额分支证据。业务读写全部使用 SQLAlchemy 声明式模型和 ORM 会话，结构迁移保留必要底层操作。

金额分支不等同于任意字段条件、并行会签、超时升级或消息调度；这些仍待独立实现。真实审批制度与金额门槛由管理员按本公司规则配置。
