# 手工总账凭证初版规则

已实现单公司、人民币手工凭证。这是本项目的内部操作规则，不自动套用法定科目或替代业务方会计政策。[正式期初余额](opening-balances.md)已独立提供；[业务来源凭证](business-journals.md)已提供草稿生成；[辅助核算](auxiliary-accounting.md)与[公司财务报表](financial-statements.md)已提供，[总账凭证附件](journal-attachments.md)已提供；[期间结账与重开](period-closing.md)已另行提供。

## 金额与期间

凭证由日期、全库唯一的依据编号、备注及 2 至 100 条分录组成。分录保存科目编号、编码、名称、类别、余额方向快照及摘要。金额使用十进制字符串，整数最多 12 位、小数最多 2 位；拒绝浮点、科学计数、负值、NaN 和静默舍入。每行借贷只能一方大于零，整单借贷合计必须相等；保存规范为两位小数。

建改、提交、批准、过账时核对日期属于开放期间，手工原凭证科目必须启用。科目名称在过账前可随资料修订刷新，过账后快照固定。期间结账后不能回填或过账该日期的凭证；历史成本保护及倒序重开见 [期间结账规则](period-closing.md)。已过账原凭证可在未来开放期间建立关联冲销，旧快照保留。

## 流程与职责分离

草稿 → 提交 → 待审核 → 批准 → 过账。待审核可驳回；草稿、驳回凭证可修改，修改恢复草稿并清除本次提交与审核字段。草稿、驳回、待审核和已批准凭证可取消，记录保留。已过账凭证不可修改、取消或再次过账。

建单、任何一次编辑或提交过此凭证的账号均不能批准或驳回此凭证，包括内置管理员。审核需另一账号获得审核权限；若审核人随后编辑了驳回凭证，也成为作者，需要第三个账号审核。过账权限独立，允许建单人或审核人过账已经批准的凭证。

每次写操作填写非空原因。新建草稿从版本 1 开始；修改与状态操作携带打开时的旧版本，成功递增版本，过期请求返回 409，不能覆盖他人修改。建立冲销时校验原凭证版本，保持原版本不变，新冲销草稿从版本 1 开始。完整前后快照、动作、原因、操作者和时间与主记录、分录同事务提交。审计失败整体回滚。结构迁移外的业务访问统一 SQLAlchemy ORM。

## 更正与冲销

已过账的原始手工凭证可建立关联冲销草稿，按原分录不可变快照交换借贷。冲销日期不能早于原凭证日期，且须属于开放期间；允许跨到另一个开放期间。原凭证保持已过账及原金额，只有冲销凭证也独立审核并过账后，两者才抵销。

同一原凭证只允许一张未取消的冲销，数据库部分唯一索引与写锁共同防止并发重复。冲销草稿不能修改分录或日期；填错时先取消，再使用新依据编号重建。停用科目仍可按历史快照冲销；不允许冲销凭证再生成冲销链。如需重录业务，另建正常手工凭证。

## 接口与权限

统一前缀 `/api/v1/finance/journals`：

| 接口 | 权限 | 行为 |
| --- | --- | --- |
| GET 空路径 | `journal.view` | 凭证列表及分录、作者、冲销关联 |
| GET `/{id}` | `journal.view` | 单张详情，用于已过账总账报表下钻 |
| GET `/options` | `journal.create` | 启用科目与开放期间选项，无需资料维护权限 |
| POST 空路径 | `journal.create` | 建立草稿，返回 201 |
| PUT `/{id}` | `journal.create` | 修改手工草稿或驳回凭证 |
| POST `/{id}/submit` | `journal.submit` | 提交 |
| POST `/{id}/approve`、`/reject` | `journal.review` | 独立批准或驳回 |
| POST `/{id}/post` | `journal.post` | 批准后过账 |
| POST `/{id}/cancel` | `journal.cancel` | 取消未过账凭证 |
| POST `/{id}/reverse` | `journal.reverse` | 建立冲销草稿，返回 201 |
| GET `/{id}/changes` | `journal.view` | 完整操作审计 |

管理员、财务员默认拥有七项权限，仍受职责分离约束。查看与写操作独立。缺失记录返回 404；输入、日期和额外字段无效返回 422；依据重复、状态、期间、停用科目、版本或职责冲突返回 409。不提供删除接口。

第 41 版仅增加 `journals`、`journal_lines`、`journal_changes` 与权限，不推断历史业务凭证、不更改库存或应收应付余额。桌面入口为“财务管理 → 总账凭证”，使用 Pinia、固定 IPC 路径和状态动作白名单；失败保留输入，撤销查看权限时清除列表。列表及详情提供原凭证、冲销凭证的双向入口。审计 API 提供完整历史快照，页面展示各次操作的日期、依据、状态、版本和借贷合计，金额保持完整不拆行。

## 验证边界

单元测试覆盖正常审核过账、非法金额与日期、借贷失衡、独立权限、全部作者禁止自审、停用及关闭期间复核、版本冲突、追加冲销、并发与审计失败回滚、旧库升级。桌面测试覆盖精确分位合计、草稿与版本、固定 IPC 和撤权清理。浏览器使用独立临时数据库验收页面，不能代替真实 Electron、会计样例核对和跨设备验收。

存在未确认期初时拒绝过账；已撤销期初而无替代方案时也拒绝过账。已确认期初约束凭证日期不得早于启用日。不曾录入正式期初的旧账可继续按原流程过账，但其历史凭证不允许再重设期初。
