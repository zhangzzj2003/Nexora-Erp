# 生产计划

生产管理的“计划类”增加独立生产计划入口 `/workspace/production-plans`。计划确定生产产品、数量及日期；物料需求计划（MRP）核算库存与用料缺口；生产工单承接审批、发料、签收、报工和完工。三者分别保留单据与审批，不用 MRP 建议代替生产安排。

## 编制与审批

一份计划包含 1 至 100 条产品安排。每行选择启用的 BOM、产量、完工目标仓库、计划开工日、计划完工日和普通／优先／紧急优先级，可关联同产品的销售订单行，也可自主备货。数量大于零、最多三位小数且不超过一百万；组件换算不能超过一百万。日期使用日历日，服务端今天按 UTC，新编或修改的开工日在今天起 730 天内，完工日在开工日起 730 天内。

生产产品下拉复用公共物料选择器，以独立宽面板按“编号”和“物料名称 / 详情”分列展示。规格、封装、品牌与料号摘要显示在名称下方，长内容自动换行，未提供资料时明确提示。保留原有关键词搜索、键盘选择、用途限制及选择产品后的 BOM 与销售来源联动；其他页面默认仍使用原有菜单。

保存时固定产品名称、单位、BOM 版本、基数、组件及下层版本引用。审批固定计划名称、备注、编制依据和完整明细；执行进度不属于批准正文，分批下达不会使剩余计划的批准失效。产品改名不改变原计划标签，配方或用途变化会在下达时重新校验。下层配方失效时，仅移除对应新建候选并提示，已有计划仍可查看与取消。

草稿、撤回或驳回且从未下达的计划可修改，修改需业务版本与原因。送审、审核、核准、批准、驳回及撤回复用单据审批窗口和模板；默认一个批准步骤，每个步骤由对应按钮权限控制。新计划的审批类型为 `ProductionPlan`。批准不改变库存。

销售来源只接受未全部交付的已确认订单。草稿也占用生产编排额度，同一销售行所有有效计划累计不能超过订单数量，新编和修改不能超过未交付数量。已发货与已安排可能是同一批产品，分别核对而不重复扣减。工单下达还会复核本次数量不超过当前未交付量。销售来源只用于数量追踪，不自动预占库存、交付订单或改变价格。

## 分批下达与更正

批准后可按产品分批生成生产工单草稿，每次携带计划业务版本、审批版本、明细编号、数量、操作依据和唯一请求编号。累计有效工单目标不得超过计划产量。重复发送同一请求只返回原结果；同一请求编号换数量或明细返回冲突。工单、关联记录、计划版本、首次审批执行事件及操作审计在同一 ORM 写事务中保存，失败全部回滚。

工单继承固定 BOM、产品数量、目标仓库及计划开完工日期，并保留上游计划编号与作者来源。工单仍需独立批准和下达，生产计划批准不自动批准工单。相同计划允许多产品、同产品多批次；一条已全部下达的历史 BOM 停用不会阻断其他产品。

已下达计划的正文不能直接修改。取消计划终止未下达部分，保留已生成工单及全部历史，已有工单继续独立执行。待审或批准但未执行的计划先撤回才能取消；首次分批下达后可直接终止余额。需要改排时终止剩余安排，再新编计划并重新审批。取消工单释放对应计划的下达额度，但不会复活已取消的生产计划。已取消计划中仍有效的工单继续占用销售编排额度，防止重新安排同一批数量。

## 执行进度

列表提供全部、待审批、待完成、延期、报工完成筛选，支持编号、名称、产品及日期搜索。详情逐产品列出计划、已下达、未下达、已报工、合格、不合格及未报工数量，附下达和变更记录。不同单位不合计成一个总数量。

列表布局与其他入库统一：统计卡片位于标题右侧，搜索和重置位于表格筛选栏左侧，刷新、关联页面入口、清空未保存输入及新建／继续编制按钮位于右侧，主操作置于末尾。重置只清除关键词与状态筛选，保留未保存计划；按钮继续遵循原有权限和忙碌、断线状态。

进度按未冲销报工累计计算：目标全部报工即为“报工完成”，包含质检不合格数量；只有合格数量进入库存。已批准且超过计划完工日、仍未全部报工的行标记延期。冲销报工后进度及延期重新计算。取消计划仍可查看既有工单的实际完成记录。此页没有自动良率补产或自动返工。

## MRP 衔接

- 仅已批准或已开始下达的有效计划进入 MRP。未下达部分在计划完工日形成预计产出，在开工日形成固定组件需求。
- 已生成且未取消的工单占用对应计划数量，该部分使用原工单剩余未报工产出和待领组件，并沿用计划日期。取消工单后其数量回到有效计划的未下达部分。
- 销售原订单需求只计算一次；计划不再额外生成一条成品需求。自主备货计划直接提供已确定的生产数量和用料需求。
- 计划或工单变化会进入 MRP 来源快照，旧固定结果需要重新核对。未下达来源因 BOM 停用、产品用途或销售状态变化而不可执行时，明确阻止读取/计算并提示计划编号；不能继续用失效供给掩盖缺料。核对来源或取消剩余安排后可重算，既有工单保留历史配方。
- 早于本次 MRP 起日的来源按起日处理，逾期产出仍显示警告。组件按各批次独立向上保留三位小数，拆批可能增加最小精度的用料尾差。

日期与数量安排不等同于有限产能排程。当前没有产线、工序、设备/人员日历、班次、甘特拖动、自动排产或交期保证。

## 权限、接口与升级

独立权限为 `production_plan.view/create/submit/review/verify/approve/release/cancel`。下达同时要求 `work_order.create`。管理员默认全部拥有，生产计划员拥有查看、编制、提交、下达与取消；自定义角色不自动增加授权。查看权包含公司生产所需的物料、仓库和销售数量来源，不返回客户资料、销售价格或金额。

接口前缀 `/api/v1/production/plans`：GET 根列表、`/options`、`/{id}`；POST 根创建、`/{id}/release`、`/{id}/cancel`；PUT `/{id}` 修改草稿。审批走 `/api/v1/system/document-approvals/ProductionPlan/{id}/{action}`。不存在返回 404，越权 403，输入错误 422，过期版本、状态、数量与来源冲突返回 409。

数据库第 107 版新增 `production_plans`、`production_plan_lines`、`production_plan_releases`、`production_plan_changes` 四张表及新权限。迁移幂等，DDL、权限和版本在同一事务回滚；不补造历史计划，不更改旧工单、旧审批正文、库存、金额或编号。下达及变更记录禁止更新、删除；计划单号写入后不可改写。

客户端和服务端需要一起升级。旧服务没有此接口时，页面显示读取失败并阻止保存，不降级为本地计划。安装服务升级、正式数据和生产现场验收独立于代码测试。

## 普通工单必须来自批准计划（v108）

普通生产统一为“编制生产计划 → 计划独立审批 → 分批生成工单草稿 → 工单独立审批与下达 → 领料、报工和入库”。计划详情的“生成生产工单”入口按批准版本、剩余额度及产品逐批生成，不能自行替换产品、BOM 或完工仓库。MRP 负责备料核算，不是每张工单的强制前置步骤。

工单页面移除自由填写产品、数量的新建表单，提供“从生产计划生成”和来源计划／排期查看；BOM 详情也只跳转生产计划。旧 `POST /api/v1/work-orders` 在权限和输入校验后返回 409，管理员也不能绕过计划。共享状态中的旧建单方法只提示前往计划，不再发送自由建单请求。

MRP 制造建议改转待审批的生产计划，要求 `mrp.convert` 与 `production_plan.create`；采购建议仍转采购申请。计划审批独立于 MRP 审批；转单人员与上游编制记录传递到下游审批依据，不能继承上游批准。工单生成继续同时要求 `production_plan.release` 和 `work_order.create`。

返工工单继续由已审批的不合格品处置生成，原数量、缺陷与处置依据保留。历史直接建单和旧 MRP 工单不补造生产计划，仍可按原审批、执行与更正规则处理；页面标识无生产计划关联。数据库 v108 保留历史转单记录，仅扩展新转单目标。需要同步升级客户端与服务端才会全面启用本规则。
