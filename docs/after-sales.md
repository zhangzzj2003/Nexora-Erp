# 售后退换修规则

## 已实现范围与边界

首版沿用单公司、人民币和移动加权平均成本。售后申请关联有效原销售出库明细，记录客户诉求、方案、数量及客户同意依据，提交后由未参与编制、修订或提交的账号独立审核；管理员同样不能自审。当前不是保修自动判定或完整服务管理系统。

- 退货：批准后生成原销售退货草稿，沿用退货确认、成本及应收更正；有效退货确认后才可结案。
- 换货：批准后生成退货草稿与同客户的新销售订单草稿。换货物料、数量及单价须明确填写，零价也须显式输入；不推断免费更换。原退货有效确认后才可确认新订单及出库，足量交付后结案。
- 维修：必须选择免费或收费并保存客户同意依据。实际收件、检验合格、实际交还分别记录操作者与凭据。客户物品独立登记保管，不进入公司可售库存。公司维修耗材生成其他出库草稿，须由仓库有效确认后才能检验合格、交付。已收件或检验合格期间可登记实际维修工时；更正追加等量反向记录，原记录不删除。

维修服务费是整单金额，不是商品单价或数量乘价；收费维修结案后向原销售订单追加应收来源。免费、取消和未交付维修不形成该费用。实收仍须人工登记，系统不连接银行。公司耗材沿用现有库存成本与其他出库凭证。实际工时只作数量与依据留痕，不自动生成收费、应付、工资或总账成本；维修项目利润和工时成本计价尚未实现。

## 权限与状态

页面 `/workspace/after-sales` 要求 `after_sales.view`。其他权限为 `after_sales.create`、`submit`、`review`、`process`、`receive`、`inspect`、`close`、`cancel`、`reverse`、`labor`。管理员默认全部拥有；销售员可编制、提交、办理、交付及取消，仓库员可收件、检验、登记和更正工时及交付，财务员可独立审核；仍可配置自定义角色。工时写入还须有查看权限及该客户的可见范围。

退换货流程为草稿 → 提交 → 批准 → 办理中 → 已交付结案；维修为草稿 → 提交 → 批准 → 已收件 → 检验合格 → 已交付结案。不合格检验保留已收件状态并追加证据。驳回后可修订并重新提交。关联单据仍校验各自权限，换货须同时具有 `sales_return.create` 和 `sales_order.create`，使用公司耗材收件须有 `other_outbound.create`。

所有写入核对整数版本。提交起占用原出库未退回数量，普通退货也核对售后占用；有效已退货只统计一次。维修交还结案或取消后释放办理占用，可用数量仍扣除有效退货；这不构成逐件保修次数限制。并发提交或重复办理不能超量或重复生成关联单据。版本冲突返回 409，应刷新并重新核对；权限错误返回 403，非法输入返回 422。

## 取消、更正和结账

办理中的退换货须先取消关联草稿；已确认退货须按原流程冲销。已交付换货须先更正换货出库，再冲销退货、取消换货订单，最后更正售后。有效售后保护原出库，不允许先冲销原出库绕过依赖。

已收件维修取消须有交付权限及实际交还依据，追加客户物品交还记录；耗材草稿先取消，已消耗公司材料保留真实记录。已结案收费维修更正保留原费用、原交接及原凭证来源，另加负向费用来源；免费维修更正保留交接历史，不产生收费或反向收费来源。两种维修更正都不再虚构一次实物交接。原收费与更正费用可分别生成业务来源凭证，角色为应收与 `repair_income`（售后维修服务收入）；无客户物品库存分录。凭证生成、独立审核及过账按现有业务凭证流程办理。

已结期间阻止历史费用更正及边界内的新保管、工时与审计记录。结账冻结截至期末最后一次方案审计、交接、工时记录、客户物品在管量、净工时与收费来源；包括尚未交付的在管物品，后续更正不覆盖原归档。

## 接口、模型与验证

统一前缀 `/api/v1/after-sales`：GET 概览；GET `/cases/{id}` 证据；POST `/cases` 建草稿；PUT `/cases/{id}` 修订；POST `/cases/{id}/{action}` 执行状态操作；POST `/cases/{id}/labor` 以十进制文本登记最多两位小数的正工时；POST `/cases/{id}/labor/{entry_id}/reverse` 更正原记录。工时接口核对版本、权限、客户归属和实际依据；交接、检验与交付操作必须填实际依据，维修检验必须明确合格或不合格。

数据库第 52 版新增 `AfterSalesCase`、`AfterSalesChange`、`AfterSalesCustody` 三张声明式模型，当时共 122 张静态 ORM 表；第 64 版新增 `AfterSalesLabor`；第 65 版增加商机概率列；第 66 版增加生产领料冲销表，当前共 148 张。业务 CRUD 使用 ORM 会话，关联草稿、版本、保管、工时与审计在同一写事务提交或回滚。迁移失败连同新表、权限及版本回滚，保留旧销售记录；不在启动时反射或重建旧表。

后端测试 `backend/tests/test_after_sales.py` 覆盖正常与更正流程、实际收费及凭证、客户物品隔离、耗材闸口、历史作者独立审核、工时精度与权限、并发占用、审计失败回滚、锁期归档及 v51/v63 升级。桌面测试 `tests/after-sales.test.mjs` 覆盖固定 IPC 路径与字段、异步身份隔离、断线保留、冲突恢复及操作权限。

## 仍未实现

保修期限、责任自动判定、序列号/实物批次、附件与图片、外发通知、物流跟踪、第三方维修、工时成本计价、自动退款、跨公司服务、税费及多币种均未实现。当前按整单收件、检验和交还；需要分批交接时应拆分售后单。
