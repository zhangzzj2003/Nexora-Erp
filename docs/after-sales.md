# 售后退换修规则

## 已实现范围与边界

首版沿用单公司、人民币和移动加权平均成本。售后申请关联有效原销售出库明细，记录客户诉求、方案、数量及客户同意依据，提交后由未参与编制、修订或提交的账号独立审核；管理员同样不能自审。系统提供有依据的保修期限核对，但不是责任自动判定或完整服务管理系统。

第 78 版可在售后草稿填写合同或承诺约定的保修天数及对应依据，两项必须同时填写；不能确认条款时均留空。以原出库快照中的 UTC 日期为起算日，加约定自然日数得到截止日（当日包含在内）；售后建单的 UTC 日期是固定申请日，驳回修订不移动申请日。期限内、已过期、未知结果随单据和审计展示。旧单没有条款时保持未知，不追认合同内容。保修期限只是审核证据，不改变独立审核、收费选择、退换货价格或财务来源；具体责任由人员依据合同和故障核定。

第 79 版允许在销售订单每条明细填写保修天数及合同或承诺依据，两项须同时填写。当前订单没有修订接口，草稿条款录错须取消重建；出库关联原订单明细，创建售后时自动带入条款并固定在来源与售后审计中，服务端拒绝售后覆盖有条款的原订单。没有条款的旧订单或新订单仍允许售后草稿人工登记经核对的依据，不会自动推断条款。升级时旧订单条款保持空白。订单条款及期限核对都不能代替故障责任或维修收费的独立审核。

第 80 版提供人工责任核定。拥有 `after_sales.review` 与查看权限、且未参与本单编制、修订或提交的人员，可对已提交且未取消或冲销的售后单记录“本公司责任、客户责任、第三方责任、暂无法判定”之一，并填写核定依据及原因。后续更正追加新记录，原结论、依据、人员和时间保留；旧单保持“尚未核定”。该记录不自动修改保修期限、审批结果、免费或收费选择、库存或财务来源，也不代替合同和故障的人工判断。

- 退货：批准后生成原销售退货草稿，沿用退货确认、成本及应收更正；有效退货确认后才可结案。
- 换货：批准后生成退货草稿与同客户的新销售订单草稿。换货物料、数量及单价须明确填写，零价也须显式输入；不推断免费更换。新订单保修条款留空，不推断原保修续期或重新起算；后续售后须另行核对依据。原退货有效确认后才可确认新订单及出库，足量交付后结案。
- 维修：必须选择免费或收费并保存客户同意依据。实际收件、检验合格、实际交还分别记录操作者与凭据。客户物品独立登记保管，不进入公司可售库存。公司维修耗材生成其他出库草稿，须由仓库有效确认后才能检验合格、交付。已收件或检验合格期间可登记实际维修工时；更正追加等量反向记录，原记录不删除。

维修服务费是整单金额，不是商品单价或数量乘价；收费维修结案后向原销售订单追加应收来源。免费、取消和未交付维修不形成该费用。实收仍须人工登记，系统不连接银行。公司耗材沿用现有库存成本与其他出库凭证。第 83 版允许财务人员对每条有效实际工时按有依据的内部标准小时成本核价，金额以人民币、两位小数和四舍五入固定；核价及撤销均追加留痕，工时反向更正后原核价保留但退出当前合计。未核价条目单独列出，不能当作零成本。核价仅用于内部成本观察，不生成收费、应付、工资或总账分录。

维修单现按已结案且未更正的服务费，减去本单有效工时内部核价与耗材出库及冲销的库存计价金额，展示人民币直接成本和直接毛利。耗材金额沿用移动加权平均计价的分位入账额，并列出流水、出库明细和计价来源；缺价流水、未核价工时或待确认的耗材出库分别显示缺口，未结案时也不计算毛利。免费结案的收入为零；收费结案后更正的收入回到零，已耗用成本仍可追溯。该观察值不产生新凭证，不包含税费、间接费用、工资凭证或维修项目完整利润。

## 权限与状态

页面 `/workspace/after-sales` 要求 `after_sales.view`。其他权限为 `after_sales.create`、`submit`、`review`、`process`、`receive`、`inspect`、`close`、`cancel`、`reverse`、`labor`、`cost`、`attachment`。管理员默认全部拥有；销售员可编制、提交、办理、交付及取消，仓库员可收件、检验、登记和更正工时及交付，财务员可独立审核、核定责任并维护内部工时成本；管理员、销售员、仓库员默认可管理附件，仍可配置自定义角色。工时、成本、附件及责任核定写入还须有查看权限及该客户的可见范围。核价人员不得为原工时登记人；内部费率与金额只通过成本权限接口读取，普通售后证据不包含它们。

退换货流程为草稿 → 提交 → 批准 → 办理中 → 已交付结案；维修为草稿 → 提交 → 批准 → 已收件 → 检验合格 → 已交付结案。不合格检验保留已收件状态并追加证据。驳回后可修订并重新提交。关联单据仍校验各自权限，换货须同时具有 `sales_return.create` 和 `sales_order.create`，使用公司耗材收件须有 `other_outbound.create`。

所有写入核对整数版本。提交起占用原出库未退回数量，普通退货也核对售后占用；有效已退货只统计一次。维修交还结案或取消后释放办理占用，可用数量仍扣除有效退货；这不构成逐件保修次数限制。并发提交或重复办理不能超量或重复生成关联单据。版本冲突返回 409，应刷新并重新核对；权限错误返回 403，非法输入返回 422。

## 取消、更正和结账

办理中的退换货须先取消关联草稿；已确认退货须按原流程冲销。已交付换货须先更正换货出库，再冲销退货、取消换货订单，最后更正售后。有效售后保护原出库，不允许先冲销原出库绕过依赖。

已收件维修取消须有交付权限及实际交还依据，追加客户物品交还记录；耗材草稿先取消，已消耗公司材料保留真实记录。已结案收费维修更正保留原费用、原交接及原凭证来源，另加负向费用来源；免费维修更正保留交接历史，不产生收费或反向收费来源。两种维修更正都不再虚构一次实物交接。原收费与更正费用可分别生成业务来源凭证，角色为应收与 `repair_income`（售后维修服务收入）；无客户物品库存分录。凭证生成、独立审核及过账按现有业务凭证流程办理。

已结期间阻止历史费用更正及边界内的新保管、工时、工时成本、责任核定与审计记录。结账冻结截至期末最后一次方案审计、交接、工时、工时核价与责任核定记录、客户物品在管量、净工时、收费来源及维修直接毛利依据；包括尚未交付的在管物品，后续更正不覆盖原归档。历史工时所在期间已关闭时须先倒序重开，才能补核内部成本。结账历史可单独授权查看，未持有 `after_sales.cost` 的账号读取时不返回内部工时核价或维修直接毛利。

## 附件留存

第 74 版为所有售后退换修单提供 PDF、PNG、JPEG 附件，单文件非空且不超过 5 MiB，每张售后单最多 10 份有效附件。上传填写来源依据；文件字节、SHA-256、操作者和时间由 ORM 保存，撤销只追加原因与操作者，历史原文继续可下载。服务端校验文件名与内容格式、重复内容、大小和摘要；桌面端只通过系统文件对话框选择本地路径，并在保存前核对下载摘要、格式及登录会话。

附件查看和导出需要 `after_sales.view` 且必须处于客户可见范围；上传与撤销另需 `after_sales.attachment`。结案、取消或更正后的售后单附件只读。附件不会改变售后版本、数量、库存、费用或独立审核结论；文件真实来源仍需人工核对。备份数据库时保留原文及撤销历史。

## 接口、模型与验证

统一前缀 `/api/v1/after-sales`：GET 概览；GET `/cases/{id}` 证据；POST `/cases` 建草稿；PUT `/cases/{id}` 修订；POST `/cases/{id}/{action}` 执行状态操作；POST `/cases/{id}/responsibility` 追加人工责任核定，提交版本、结果、依据和原因；POST `/cases/{id}/labor` 以十进制文本登记最多两位小数的正工时；POST `/cases/{id}/labor/{entry_id}/reverse` 更正原记录。GET `/cases/{id}/labor-cost` 读取受限的逐条核价、缺口及历史；POST `/cases/{id}/labor-cost/{entry_id}` 提交版本、十进制小时成本或 `null` 撤销、原因与依据；GET `/cases/{id}/repair-margin` 只读汇总已确认服务费、工时核价与耗材计价，要求 `after_sales.cost`、`after_sales.view` 和客户可见范围，非维修单返回 409。GET/POST `/cases/{id}/attachments` 查看和上传附件，GET `/cases/{id}/attachments/{attachment_id}` 读取原文，POST 后缀 `/reverse` 追加撤销。责任核定、工时与核价接口核对版本、权限、客户归属和实际依据；交接、检验与交付操作必须填实际依据，维修检验必须明确合格或不合格。

数据库第 52 版新增 `AfterSalesCase`、`AfterSalesChange`、`AfterSalesCustody` 三张声明式模型，当时共 122 张静态 ORM 表；第 64 版新增 `AfterSalesLabor`；第 74 版新增 `AfterSalesAttachment` 和 `AfterSalesAttachmentReversal`，当时共 170 张静态模型表；第 75 版增加报价附件后为 172 张；第 76 版增加其他 CRM 资料附件后为 174 张；第 77 版增加设备维护附件后为 176 张；第 78 版给售后单新增保修天数和依据列；第 80 版新增 `AfterSalesResponsibility`，当时共 177 张；第 81 版新增销售订单合同正文版本后为 178 张；第 82 版新增合同版本附件及撤销两张表，第 83 版新增 `AfterSalesLaborCost`，全库共 181 张。业务 CRUD 使用 ORM 会话，核价、版本及审计在同一写事务提交或回滚；附件单独使用写事务保留原文与撤销记录。迁移失败连同新表、权限及版本回滚，保留旧销售与工时记录；不在启动时反射或重建旧表。

后端测试 `backend/tests/test_after_sales.py` 覆盖正常与更正流程、实际收费及凭证、客户物品隔离、耗材闸口、历史作者独立审核、工时精度与权限、维修直接毛利及缺价/客户范围、并发占用、审计失败回滚、锁期归档、保修期限、订单条款传递、责任核定的更正与归档及 v51/v63/v77/v78/v79 升级；`backend/tests/test_after_sales_attachments.py` 覆盖附件内容、权限、客户范围、撤销和 v73 升级。桌面测试 `tests/after-sales.test.mjs`、`tests/customer-catalog.test.mjs` 与 `tests/after-sales-attachments.test.mjs` 覆盖固定 IPC 路径与字段、保修条款带入、人工责任核定、异步身份隔离、断线保留、冲突恢复、附件摘要和操作权限。

## 仍未实现

销售合同原件已可按版本留存，但签署验证与条款自动提取、责任自动判定、序列号/实物批次、外发通知、物流跟踪、第三方维修、人工成本总账归集与维修项目完整利润、自动退款、跨公司服务、税费及多币种均未实现。人工责任核定目前不自动决定收费或责任赔付。当前按整单收件、检验和交还；需要分批交接时应拆分售后单。
